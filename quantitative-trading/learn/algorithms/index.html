①

截面动量

Cross-sectional momentum · Jegadeesh & Titman 1993
一句话同一时点给所有标的排序，买相对最强、卖相对最弱，定期重排。先做这个——五十行能写完，数据免费，而且它踩的坑你之后都会再遇到。
开始之前：把三层分清楚 ① 原文结论：按过去 3–12 个月收益排序、持有 3–12 个月获得显著正收益；最详细考察的 6 个月排序 / 6 个月持有设定报告年均约 12.01% 的复合超额收益。
② 原文设定：形成期与持有期之间跳过一周，用于规避买卖价差、价格压力与滞后反应。
③ 下面写的：今天通行的 12-2 教学惯例（跳过最近一个月）， 是后续文献标准化的结果，常与 Fama-French (1996)、Carhart (1997) 一并引用——不是 1993 年论文的算法。

本专题最初版本混淆了 ② 和 ③。看到一个规则，先问它是论文里的，还是教材里的。

参考实现：先看一个会报错的版本

这段代码是坏的 —— 本专题此前就写成了这样 
# ✗ 形状错误：第二行把 Series 变成了 DataFrame
score = R.loc[t-12 : t-1, universe].sum()          # → Series，索引是标的　✓
score = score / vol.loc[t-12 : t-1, universe]     # → Series ÷ DataFrame
                                                 #   = DataFrame（月 × 标的）✗
ranks = score.rank(pct=True)                       # 在 DataFrame 上按列排 → 跨月排序，语义也错了
w[ranks > 0.9] = +1.0                             # 用 DataFrame 掩码索引 Series → 直接报错
三个独立的错误叠在一起：① 简单收益直接 sum() 而没有复利； ② 波动率没有先收敛成「每个标的一个数」，导致广播成二维； ③ .loc 的标签切片包含右端点，和整数偏移混用时窗口边界会悄悄错一格。

还有第四个，更隐蔽：用 ranks > 0.9 和 ranks < 0.1 选两端， 看起来对称，其实不是。rank(pct=True) 的最小值是 1/N 而不是 0，所以：

· N = 10：分位是 0.1, 0.2 … 1.0 → 多头选中 1 只，空头 0 只（0.1 不满足 < 0.1）。 归一化之后净敞口 = +1，这是一个纯多头仓位，和注释里写的「净敞口 0」正好相反。
· N = 100：多头 10 只、空头 9 只，仍然是偏的。

这类错误不会报错，只会安静地把一个多空策略变成带方向暴露的策略， 然后你在回测里看到的其实是市场 beta。修正版改成两端各取相同数量，并用两条 assert 守住。

第五个，同一类毛病：prod() 和 std() 也默认跳过 NaN。 一只刚上市两个月的新股会用 2 个观测算出动量与波动，然后和有 11 个月历史的票排进同一张榜—— 分数根本不可比，而且同样不报错。修正版先要求形成窗口完整再打分。
规律：pandas 里所有「默认跳过缺失值」的聚合，在回测里都是隐患， 因为缺失恰恰集中在退市、停牌、新上市这些最影响结论的地方。

修正版

import pandas as pd
import numpy as np

# ── 约定写死在这里，不要靠记忆 ──────────────────────────────
#   R         月频「简单收益」DataFrame，index=月末时间戳，columns=标的
#             必须是 point-in-time：含已退市标的，成分股用当时的名单
#   决策时点  月 m 收盘（m_idx 是 R.index 上的位置下标）
#   形成窗口  月 m-11 … m-1，共 11 个月
#   跳过      月 m —— 12-2 惯例（后世标准化，非 JT1993 原文）
#   持有      月 m+1，赚取该月收益
FORMATION, SKIP, TOP = 11, 1, 0.10
WARMUP = FORMATION + SKIP - 1          # = 11，第一个能真正决策的月份

def target_weights(R, m_idx, universe):
    lo = m_idx - FORMATION - SKIP + 1
    hi = m_idx - SKIP + 1                  # iloc 右端不含 → 最后一个月正好是 m-1
    if lo < 0:
        return pd.Series(0.0, index=universe)

    win = R.iloc[lo:hi][universe]           # DataFrame：11 个月 × 标的

    # ① 先要求形成窗口**完整**。pandas 的 prod() 和 std() 默认跳过 NaN，
    #    所以一只上市两个月的新股会拿 2 个观测算出分数，然后和有 11 个月
    #    历史的票排在一起 —— 分数不可比，而且不会报错。
    complete = win.notna().all()            # → 每个标的一个 bool
    win = win.loc[:, complete]
    if win.shape[1] == 0:
        return pd.Series(0.0, index=universe)

    mom   = (1.0 + win).prod() - 1.0      # ② 简单收益要复利 → Series
    sigma = win.std()                       # ③ 先收敛成每标的一个数 → Series
    score = (mom / sigma.replace(0.0, np.nan)).reindex(universe)

    # ④ 一条便宜的护栏：形状错了立刻炸，而不是安静地给出错误结果
    assert isinstance(score, pd.Series), "score 必须是标的维度的 Series"

    # ⑤ 两端各取「相同数量」，而不是各取一个分位阈值
    valid = score.dropna().sort_values()         # 升序；并列由 sort 的稳定顺序决定
    k = max(1, int(round(len(valid) * TOP)))
    if len(valid) < 2 * k:                       # 有效标的不足以两端各取 k 只
        return pd.Series(0.0, index=universe)   # 本期不交易，而不是勉强建一个偏的仓

    w = pd.Series(0.0, index=universe)
    w[valid.index[-k:]] = +0.5 / k              # 多头腿合计 +0.5
    w[valid.index[:k]]  = -0.5 / k              # 空头腿合计 −0.5
    assert abs(w.sum()) < 1e-12                # 净敞口 0
    assert abs(w.abs().sum() - 1.0) < 1e-12   # 总敞口 1
    return w


# ── 回测循环：成交与收益的时点必须显式写出来 ─────────────────
# 口径：w 是相对「期初、扣费前 NAV」的目标权重，费用从现金支付。
held = pd.Series(0.0, index=R.columns)          # 交易前的**实际**持仓权重
for m_idx in range(WARMUP, len(R) - 1):        # ← 跳过形成窗口不足的热身期
    uni = liquid_names_as_of(R.index[m_idx])         # 当时可交易、成交额达标
    w   = target_weights(R, m_idx, uni).reindex(R.columns).fillna(0.0)

    # ⑤ 换手要对着「漂移后的实际持仓」算，不是对着「上期的目标」
    turnover = (w - held).abs().sum()
    cost     = turnover * (half_spread + impact_bp) / 10_000

    # ⑥ 持有期收益缺失不能默认跳过：pandas 的 sum() 会把 NaN 当 0，
    #    而 NaN 恰恰最常出现在退市、停牌、数据缺口 —— 也就是最该亏钱的时候。
    r_next = R.iloc[m_idx + 1]
    missing = r_next[w != 0].isna()
    if missing.any():
        raise ValueError(f"持仓标的缺少 m+1 收益：{list(missing[missing].index)}")
        # 生产环境应改为显式填入退市收益，而不是让它静默变成 0

    gross = (w * r_next).sum()                       # ← 赚的是 m+1 的收益
    net_r = gross - cost
    net.append(net_r)

    # ⑦ 下一期开盘前，权重已经被价格和费用一起推走了。
    #    只对**有持仓**的标的算漂移：未持仓标的若收益是 NaN，
    #    0 * NaN 会变成 NaN，而 (w-held).abs().sum() 又会跳过 NaN，
    #    结果下一期首次买入这只票的换手会被整笔吞掉。
    held = pd.Series(0.0, index=R.columns)
    pos  = w != 0
    held.loc[pos] = w[pos] * (1 + r_next[pos]) / (1 + net_r)
第 ⑤ ⑦ 步：为什么不能写 held = w 持有一期之后，即使目标权重一个字没改，实际持仓也已经不是 w 了—— 价格涨的那些仓位占比变大，跌的变小，同时扣掉的费用还让 NAV 缩了一点。 回到目标需要真实交易，而写 held = w 会把这段换手记成 0，系统性低估成本。

三个手算（前两个在本页配套实验里是断言）：
· 目标 [0.5, −0.5]，本期收益 [+20%, −10%]，零成本 → 漂移后约 [0.5217, −0.3913]，回到目标需换手 0.1304。
· 目标不变、价格完全不动、换手 1.0、成本 100bp → NAV 变成 0.99， 持仓权重变成 ±0.5/0.99，回到目标仍需换手 0.0101。 所以漂移的分母必须用净收益 1+gross−cost，不是 1+gross。
· NaN 会吞掉整笔开仓换手。三只票 A/B/C，第一期目标 [0.5, −0.5, 0]， A/B 收益 0、C 收益缺失但本期本来就没持仓；第二期目标 [0, −0.5, 0.5]、 三只收益均为 0、成本 100bp。
　正确：第一期净 −1%，漂移后 [0.5051, −0.5051, 0]； 第二期换手 1.0101、净 −1.0101%。
　若对全列算漂移：C 的 held 变成 0 × NaN = NaN， .abs().sum() 又会跳过它 → 第二期换手只剩 0.5101、净 −0.5101%， C 那笔开仓的成本凭空消失了。
　注意：这不能靠「把所有缺失收益填 0」绕过——那会把退市当成没涨没跌。 持仓标的缺收益必须报错，未持仓标的的 held 保持 0。
为什么简单收益不能直接相加？（点开，30 秒）

两个月分别 +50% 和 −50%。

相加
0.5 + (−0.5) = 0 → 结论「打平」
复利
1.5 × 0.5 − 1 = −0.25 → 实际亏了 25%

什么时候可以相加：用对数收益 ln(1+r) 时可以直接求和， 因为 ln(ab) = ln a + ln b。所以两条路都对，但必须写明用的是哪一条—— 混用是回测里非常隐蔽的一类错误，幅度小到不会报错，大到足以改变结论。

中性化：当作对照实验做，不要当作定义

修正一处过强的表述 本专题此前写过「不做行业中性化，你测的就只是行业轮动」。这话说得太绝对了。 行业暴露占多大比重是个经验问题，取决于市场、时期与标的池，应当用数据回答而不是靠断言。

正确做法是跑一组对照：
变体怎么构造它回答什么
A · 原始动量只按 mom 排序基线
B · 波动率缩放mom / sigma风险调整贡献了多少
C · 行业中性在每个行业内部排序，或对行业哑变量回归取残差扣掉行业后还剩多少
D · 全因子中性再回归掉 beta、市值扣掉全部已知因子后还剩多少

把 A→D 的收益、Sharpe、换手并排列出来。如果 C 相对 A 损失了大部分收益， 那么对这个市场、这段样本而言，你的信号确实主要是行业暴露——这是一个被数据支持的结论， 而不是一句先验的断言。如果 C、D 依然稳健，那你手上的东西更可能是真的。

已知失效模式 · 动量崩溃 动量的收益分布是左偏的：平时小额稳定盈利，在市场从极度恐慌急速反转时 （典型如 2009 年 3 月起的数月），你做空的「输家」是被打到低位的高 beta 股票，反弹最猛，空头端集中亏损。 这个形状和卖保险是同构的。

标准缓解手段是波动率目标（实现波动上升就自动降杠杆）与状态相关的暴露调整。 注意这不是「加个止损」——止损处理单笔仓位，这里处理的是整个策略的尾部形状。
动手 可运行实验实现的正是这个算法（纯标准库，无需 pandas）。 它把上面的时间口径写死并用断言守住，然后展示一件更重要的事： 在完全没有动量的合成数据上，这个策略单跑仍然可能做出正收益。

统计套利

Statistical arbitrage · Avellaneda & Lee 2010
一句话不去猜哪只票会涨，而是先把所有共同因素扣掉，只交易剩下的残差——因为残差才是真正有理由均值回复的东西。

配对交易的直觉人人都懂，但它有个致命弱点：你怎么知道该配哪一对？ 500 只股票有 124 750 个配对，按历史协整强度排序选出的头部，绝大部分是多重检验的产物。 问题不在配对交易这个想法，在于「遍历筛选」这个发现机制本身就在制造假阳性。

Avellaneda & Lee 给的工业级答案是：不要找配对，去找共同因子。

OU 过程、κ、半衰期、s-score 分别是什么？（点开）
先问
「这个偏离会回来吗？多久回来？现在偏得算多还是算少？」——四个符号各回答其中一问。
OU 过程
连续时间版的「均值回复」。dX = κ(m − X)dt + σdW 读作：X 每一刻都被往 m 拉，拉力正比于它离 m 有多远，同时被随机噪声推来推去。离得越远，拉力越大。
κ
回复速度，单位是 1/时间。κ 越大，拉回得越快。怎么估：对残差的累计和做一个 AR(1) 回归 Xt = a + b·Xt−1 + ε，则 κ ≈ −ln(b) / Δt。
半衰期
ln2 / κ。含义是「当前偏离缩小一半平均需要多久」。这是最实用的一个数：它直接告诉你持仓期该设多长，也给了时间止损的标尺（超过 2–3 倍半衰期还没回来，说明模型对它已经不成立）。
s-score
s = (X − m) / σeq，就是 z-score。它的价值不在单个数字，在于可比：标准化之后，一只银行股和一只矿业股的偏离程度可以直接放在一起排序。这正好提高了主线那条公式里的 BR（广度）。
一个手算
某股残差累计 X = 6，历史 m = 0、σeq = 2 → s = 3，偏离 3 个标准差，触发开空。若 b = 0.9（月频），则 κ ≈ 0.105/月，半衰期 ≈ 6.6 个月——这个持仓期长得超出多数人预期，也说明为什么必须配时间止损。

做市

Optimal market making · Avellaneda & Stoikov 2008
一句话同时挂买单和卖单赚价差。技术含量不在报价，在库存管理——不过库存只是这个模型显式定价的那一种风险，成交的随机性和逆向选择都在它之外。

前两个算法都在猜方向，做市不猜。但有两件事会杀死你：

  • 库存风险：如果只有卖方来找你，你会不断买入、越攒越多，然后价格继续跌。价差利润远小于库存亏损。
  • 逆向选择（Kyle 1985 的核心洞察）：愿意立刻跟你成交的人，往往是知道得比你多的人。你的对手方里混着知情交易者，他们会系统性地在你报错价时来吃你的单。
q、γ、k 分别是什么，实盘里怎么定？（点开）
q · 库存
你当前净持有多少。q 出现在保留价格里，符号决定了报价往哪边偏。
但别把它当成唯一风险：库存只是这个模型显式定价的那一种风险。另外两种它没管——① 成交本身是随机的（订单以 A·exp(−k·δ) 的强度到达，你不知道会成交多少、哪一边成交），所以价差收入是期望值而不是确定收入；② 逆向选择完全在模型之外，而它不能被归约成库存的价格波动。本页下面「这个模型没有告诉你的事」那一节讲的就是第 ②。
γ · 风险厌恶
调大 → 价差变宽、库存压得很紧 → 成交少但安全；调小 → 价差窄、敢攒库存 → 成交多，但大行情时会很痛。怎么定：从你能承受的最大库存 qmax 反推——让 q 接近 qmax 时，报价偏移大到足以强制平仓。
k · 订单流敏感度
描述「报差一点，成交少多少」。k 大 = 稍微报差就没人跟你成交 → 必须报窄；k 小 = 报宽也有人成交 → 可以多赚价差。怎么估：从历史订单簿数据拟合 成交率 ≈ A·exp(−k·δ)，对 δ 分桶回归。
σ · 波动率
用短窗口实现波动而不是长期均值。波动突变时必须能立刻反应——这是活下去的关键，也是把这个模型用坏的最常见方式。
T−t · 剩余时间
方向和直觉相反，容易实现反。偏移项是 qγσ²(T−t)，越接近收盘 T−t 越小，偏移就越小——在这个模型里，临近收盘时报价反而回归对称。
为什么：模型的库存惩罚来自「剩下这段时间里库存还要承受多少价格风险」，时间越短、风险越小。它没有建模「收盘必须平掉库存」这件事。
如果你要的是「临近收盘更急着甩货」，那得另外加一个终端库存惩罚或强制平仓规则，而不是指望这一项。照着这个公式实现却期待收盘加速，会把时间依赖写反。
单位约定
先把单位说清楚，否则这个公式很容易算错一个数量级。原论文的价格过程是 dS = σ dW，所以 σ 是「价格单位 / √时间」，不是收益率；q 是股数；qγσ²(T−t) 的结果是价格单位的偏移，要再除以中间价才得到相对偏移（bp）。γ 的单位必须与你选的财富/库存口径一致。
一个手算
取中间价 S = $100、σ = $2/√天（即日价格波动约为价格的 2%）、T−t = 0.5 天、库存 q = +5 股：
偏移 = q·γ·σ²·(T−t) = 5 × γ × ($2)² × 0.5 = 10γ 美元
· γ = 0.01 → 偏移 $0.10，相对 $100 是 10 bp
· γ = 0.10 → 偏移 $1.00，相对 $100 是 100 bp（1%）
结论：偏移对 q 和 γ 都是线性的，而绝对量级完全由 γ 决定。所以 γ 必须从你真实能承受的最大库存反推，照抄论文里的数字会得到一个要么完全不管库存、要么一有仓位就疯狂报偏的做市商。
易错点
把 σ 当成「日收益率标准差 2%」直接代入，得到的偏移会小几个数量级——本页早先的版本就犯过这个错。波动率的时间单位也要分清：「日收益标准差」与「每 √天 的价格波动」不是一回事。
这个模型没有告诉你的事 它假设订单流是外生的、与价格无关的泊松流。现实里不是。 真实市场中成交与后续价格变动是相关的——这就是逆向选择。 模型里没有「知情交易者」这个角色，所以它系统性低估了做市风险。

把它当骨架，不要当完整答案。真实做市系统还需要：微观价格（按买卖量交叉加权，而非简单中间价）、 订单流不平衡信号、有毒流检测、以及能在亚毫秒内撤单的基础设施。

诚实提醒：做市是三个算法里最不适合个人做的。它对延迟、费率返佣、交易所直连的依赖， 使它本质上是一门基础设施生意。学它是为了理解市场怎么运转（这对做前两类策略极有帮助）， 而不是明天去和专业做市商抢单。
自测：为什么要用「微观价格 microprice」而不是简单中间价 (bid+ask)/2？

因为买卖两边的挂单量携带方向信息。假设买一有 10000 股、卖一只有 100 股，中间价说「公允价在正中间」， 但常识告诉你：卖方的量马上会被吃光，价格下一刻更可能向上走。

微观价格用两边的量做交叉加权：(P_bid × V_ask + P_ask × V_bid) / (V_bid + V_ask) ——量大的那一边把价格往对面拉。

为什么这对做市至关重要：如果你用中间价当锚，在订单簿严重失衡时你的买单会被系统性地「选中」成交， 然后价格立刻朝不利方向走。这就是逆向选择的具体表现形式，换用微观价格是最便宜的第一层防御。
