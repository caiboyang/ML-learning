The replication evidence
一句话「发现时就有很多是假的 → 用严格方法重做大部分复制不出来 → 就算是真的公开后也被套利掉大半」。三段都被量化过。
45

t > 3.0

02

Deflated Sharpe Ratio：它到底要什么输入

DSR · 这一节修正了本专题此前的一个错误
一句话试验日志是必要的研究记录，但不足以单独算出 DSR——它还需要样本长度、收益的偏度峰度，以及试验之间的相关性处理。
先纠正一处 本专题早先的版本把「日期 / 改动 / 样本内 Sharpe」这样一个 CSV 称为 「DSR 的唯一输入」。这是错的。 那份日志能提供试验次数和各次 Sharpe 的分布，但恢复不出被选中策略的收益序列， 因而算不出偏度、峰度与样本长度这三个 DSR 必需的量。

正确说法：试验日志是必要条件，不是充分条件。下面给出最小记录清单。
DSR 想解决什么问题？（点开）
问题
你报告了一个 Sharpe = 1.2。但这个 1.2 是从 1 个候选里挑的，还是从 500 个里挑出来的最大值？这两种情况下同一个数字的含义完全不同，而通常没人告诉你。
思路
如果你试了 N 次，那么即使所有策略的真实 Sharpe 都是 0，最大值也会因为纯粹的运气而明显大于 0。这个「靠运气能到多高」的期望值可以算出来，它取决于 N 和各次试验 Sharpe 的离散度。
输出
把你观察到的 Sharpe 与那条运气基准做比较，得到一个概率：「这个 Sharpe 显著大于纯运气」的可信度。
还修了
收益的非正态性。负偏 + 厚尾（大多数策略的形状）会让普通 Sharpe 系统性高估，DSR 一并修正。
出处
Bailey & López de Prado (2014)，看式 (2) 与 A Numerical Example 一节。

最小记录清单 · 想事后算 DSR，这六项当时就得存下来

#记录什么为什么 DSR 需要它只存日志会怎样
1每次试验的收益序列（或足够统计量：均值、标准差、偏度、峰度、期数）偏度与峰度直接进 DSR 的修正项恢复不出来，DSR 算不了
2样本长度（观测期数）与采样频率（日 / 周 / 月）Sharpe 的估计误差 ∝ 1/√T；年化换算也依赖频率同上
3试验次数 N，以及每次的配置与数据版本运气基准随 N 上升日志能给
4各次试验 Sharpe 的方差与 N 一起决定「最大值的期望」有多高日志能给
5试验相关性 / 有效独立次数的处理方法试验通常高度相关（改一个参数不算一次全新尝试）。原作者建议用无监督方法估计有效独立试验数，直接用 N 会低估膨胀日志不含这个判断
6费用与无风险参照口径、样本区间起止决定这个 Sharpe 是毛的还是净的、超额相对谁最容易漏，也最容易让两个数字不可比
最低限度的可执行版本 如果你只肯做一件事：每次回测把收益序列存成一个 parquet/csv，文件名带上配置哈希与日期。

这一个动作同时满足了第 1、2、3、6 项。剩下的第 4 项可以事后从这些文件算出来， 第 5 项是一个需要你自己判断的方法选择。
对 ADHD 友好的退化版本：至少记下「今天试了几次」这一个数字——它远好过不记， 虽然不足以算 DSR，但足以让你在报告 Sharpe 时诚实地加一句「这是从 N 个里挑的」。
03

按症状查表：七种回测偏差

Bias lookup table · 每做一个策略过一遍
偏差症状怎么发生的修法
前视 / 未来函数Sharpe 高得离谱（> 3），回撤极小 用了当时还不存在的数据：财报按报告期而非发布日；复权因子含未来信息；标准化时用了全样本统计量 全部改成时点数据；任何 fit 只能用截至 t 的信息
幸存者偏差长期回测收益系统性偏高 标的池只含今天还活着的标的，退市、破产、下架的全被剔除 用含退市记录的数据库；标的池必须是当时的成分股
多重检验 / 过拟合参数稍微一动收益就崩 试了 N 次只报最好的那次 记录尝试次数；用 DSR 折算；看参数高原而非尖峰
数据窥探样本外也不错，但实盘不行 你的「样本外」其实已被反复使用——每次失败后你就回去改模型 留一段从未看过的数据，只在最后用一次，用完作废
成本低估高换手策略特别好看 只扣手续费，没扣价差和冲击 按 |Δw| × (半价差 + 冲击估计) 扣；做成本 ×2 / ×3 压力测试
成交假设过于乐观回测能在最高/最低价成交 假设限价单一定成交、涨停板能买到、忽略排队 成交按下一根 bar 的价格或更差；限价单按保守成交概率
标签泄漏（ML 特有）交叉验证准确率异常高，样本外骤降 训练/测试随机切分，但金融标签在时间上高度重叠——测试集的答案部分写在训练集里 Purged K-Fold + Embargo，见下节
Purged K-Fold + Embargo 在解决什么？（点开）
问题
金融标签通常跨越多天。比如标签是「未来 5 日收益」，那么第 1 天和第 3 天的样本共享了 3 天的价格路径。随机切分时第 1 天进训练集、第 3 天进测试集，测试集的答案已经部分写在训练集里了。
Purging
切分时删掉训练集里与测试集在时间上重叠的样本。
Embargo
在测试集之后再留一段隔离期不用于训练。因为序列相关会让信息往后泄，紧贴着测试集末尾的训练样本仍然受污染。
直接后果
sklearn.model_selection.cross_val_score 的默认行为在这个场景下是错的。必须换成 purged 版本。
出处
López de Prado,《Advances in Financial Machine Learning》第 7 章。

七步流程：可以直接照着做

A runnable checklist
#步骤通过标准
1先写下假设，再碰数据能用一句话说清谁在亏钱给你、为什么他愿意。写不出来就别做
2切三段：训练 / 验证 / 留出留出段覆盖多个市场状态；并且你事先承诺「结果不好就放弃」
3记录每一次尝试见上面的最小记录清单。至少存下收益序列
4看参数高原，不看参数尖峰扫成热力图；真信号是一片连续好区域，过拟合是一个孤立亮点
5破坏性检验收益序列打乱后策略应归零；信号取反后收益应大致对称变负
6纸上交易 1–3 个月暴露回测里看不见的：数据延迟、断线、涨跌停、流动性消失、你自己在亏损时的行为
7上线后按模块归因实盘与回测的差异能拆成 alpha / 风险 / 成本 / 执行 四项。拆不开就永远在猜
第 2 步的括号才是全部 留出集的有效性完全依赖那句事先承诺。 如果留出段表现不好时你的反应是「回去继续改」，那它已经不是留出段了， 只是第二个验证段，统计意义归零。

这是流程里唯一无法用代码强制的一环——它是纪律问题，不是技术问题。 所以请把承诺写下来，写在实验日志的第一行，而不是留在脑子里。
05

在你自己的机器上看一遍

Runnable · 纯标准库，无需联网或账户
一句话这个实验的默认模式故意不含任何信号。先看它在纯噪声上交出什么，你才有理由相信它在有信号时给的数字。
python3 quantitative-trading/lab_momentum.py            # 数据里没有动量
python3 quantitative-trading/lab_momentum.py --signal   # 数据里有动量

它会做五件事：① 跑五项自检（含「改掉未来数据不影响过去决策」的未来函数检查）； ② 成本 0 / 10 / 30bp 三档对比；③ 与同区间同成本口径的买入持有基线对比； ④ 画出净值曲线；⑤ 换 40 个随机种子重跑，把 长样本（240 个月）与短样本（60 个月）的 Sharpe 分布并排画出来。

最重要的是第 ⑤ 步的输出 数据里没有任何动量结构，策略的真实期望收益是 0。但你会看到：

· 单跑仍然可能做出正收益和正 Sharpe——这不是 bug，这就是噪声的样子；
· 长样本分布窄，短样本分布宽得多，最幸运的种子能跑到 Sharpe 1 以上。

把「种子」换成「你调过的参数」，这就是主线第 09 步那条 「5 年数据 + 45 次尝试 = 一个假 Sharpe 1」的机制，在你自己机器上重现一遍。

两条直接可用的推论：样本越短，你越容易骗到自己；单次回测结果不是证据，分布才是。

然后加 --signal 再跑一次，看同一套代码能不能把真信号和这团噪声分开。
这个实验不是什么 它用的是固定种子的合成数据，生成规则已知。它验证的是回测流程本身—— 时间顺序对不对、成本扣没扣、基线公不公平——不是任何论文的复现，也不构成样本外业绩证据。 真正的研究任务是：预选资产池与区间、冻结规则、在时点正确的真实数据上做时间外推、审计成本与基线。
