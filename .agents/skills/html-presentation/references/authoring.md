# 写作与视觉规范

## 先建立听众需要的主线

口播的切入口、论证主线和逐页展开见 [通用口播方法](speechwriting.md)。本文件负责将这些内容变成适合投影和朗读的两个视图。

- 若使用演讲者的真实经历或项目，先说明它与听众的关系，再展开；没有这些材料时可直接从任务、证据或问题进入，不编造身份和经历。演讲者不一定是 builder，主题不一定是技术。
- 真实产品介绍、具体 bug、开发辅助工具的输出分清。技术细节只有推动论点时才保留。
- 例子使用事实与人做的选择。迭代案例展示“为什么改、改了什么、是否解决”，不是堆版本号或做工具使用教学。
- 先看用户给的真实材料和代码，再作产品判断；不把演示结果说成正式发布或验证成功。
- 故事之间用一句可直接读出的短转场。不要每次重新自我介绍；不要重复同一个市场比较或验收清单来填时间。
- 非母语演讲者优先常用词、短句、主动语态。把 native-sounding 长句拆成可一口说完的句子。保留用户的自然语气，不擅自变成课堂互动；需要互动先沿用明确约定。
- 技术抽象用可见变化表达：build 时间很长用长条表示；试错更便宜用短步和闭合循环表示；AI 的价值用“反馈 → 查找 → 行动 → 检查”表示。循环必须有返回路径，动画只强化顺序。新闭环直接用 [动态 loop 组件](../assets/components/loop.html)，保留流动轨迹、依次强调和条件返回；不要退化成静态箭头或旋转符号。

## 一份内容，两个视图

| 内容 | 观众投影 | 演讲者讲稿 |
|---|---|---|
| 主张 | 大标题，一眼看懂 | 用短句展开 |
| 例子 | 一张图/一个流程/几组关键词 | 必要上下文和为什么 care |
| 操作 | 无需演讲者逐个点击 | 中文黄色【动作】放在对应口播之前 |
| 来源/范围 | 必要时简短脚注 | 非口播提醒单独放，不能让人误读 |
| 时间 | 不显示工具栏 | 总用时、本页用时、预算与估算分开 |

默认英文演讲正文、中文舞台提示，实际语言遵循用户。`say` 必须是要讲的话；`cue` 只放停顿、指向、翻页、播放和可选分支提示。不要把 “This is only an example…” 之类内部免责声明塞进正文，除非听众真的需要听到它。

## 视觉基准与改动边界

用户认可的现有演讲就是视觉基准。开始新增页面前，挑选有代表性的标题页、实物插图页和流程页作对照，记录配色、字体层级、插图笔触、文字密度和动画节奏。保留已认可的布局、字体、字数、插图笔触和动画。配色是独立的主题选择：同一演讲延续已选配色，新演讲根据学校、品牌和用户偏好选择；不能把绿色固化为方法论。修改颜色不自动授权改变其他视觉特征。

本包的调性是大字、宽留白、少字；暖纸色与森林绿只是 `forest` 示例，另有 blue、plum 及自定义颜色，详见 [配色指南](color.md)。空调、冰箱等生活物件用简化几何轮廓、克制阴影和少量细节表达。参考 [实物插图样张](../assets/illustration-reference.html)，样张提取自已认可的演讲；复用画法，不把这些物件强加给不相关主题。不要换成写实照片、炫光科技背景、通用 emoji 或密集卡片。新图继续用具体、可识别的对象解释一个关系，标签保持短，机制与限定放入口播。

对照样张检查文字密度，不设通用“每页必须填满多少字”。短标签、单位、必要字幕可以保留；不要把“少字”解释为取消必要信息。说明文字过多时先精简口播与页面分工，不能自动缩字或新增页面，尤其在最终排练阶段。

## 视觉系统

- 按用途分配深/浅背景、正文、次要文字和强调色，同一角色全篇一致。`forest` 示例使用深森林绿、暖纸色、薄荷绿和少量珊瑚色；用户可选择其他配色，不改变版式。
- DM Sans 主标题 + Libre Caslon Display 的强调行；DM Mono 用于页码、小标签。CSS 带系统字体 fallback；网络字体加载失败不应阻止演讲。
- 桌面标题约 68–104px，正文关键词约 28–36px；先删字和拆页，不靠缩小字体塞满。
- 宽留白、巨大标题、细线连接和少量色块；不堆装饰卡片、图标和密集 bullet 列表。
- 一屏一个重点。图、字幕、二维码以投影可读为准；二维码留足白边，扫码目标文字可见。真实 logo/QR 由用户提供或按明确目标生成，不随模板传播。
- 演讲者页以高对比的深底大字口播为主，小缩略图辅助定位。桌面两栏按左后右；窄屏改为单栏，溢出时可滚动，不能裁掉句子。
- 翻页 smooth scroll 与内容淡入保留；远程切页也走相同路径。不要让远程切页退化成瞬移。尊重 reduced-motion，缩略图静态可见。

## 时长与最后阶段

- 模板的估算只统计英文 `say`；中文 cue 不计词。按 100–120 英文词/分钟是显式假设，不是对每位演讲者的测量。
- 视频单独计时，Q&A 单独留时间；一页的预算不能证明口播能讲满。正式标注依彩排修订。
- 最后阶段只改用户指出的内容。删重复页时同步生成页码、缩略图、转场和目录；不要顺手增加新章节、改其余故事、重做整体 UI。
