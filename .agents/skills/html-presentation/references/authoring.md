# 写作与视觉规范

## 先建立听众需要的主线

每页回答：听众已经知道什么，这页增加了什么，下一页为什么跟得上？一般可用「听众关心的问题 → 亲身例子 → 例子说明的变化 → 可带回工作的做法 → 展望」。这是起点，不是强制目录。

- 解释 builder 的视角为什么对非技术听众有用；先让他们知道为什么 care，再讲自己的项目。
- 真实产品介绍、具体 bug、开发辅助工具的输出分清。技术细节只有推动论点时才保留。
- 例子使用事实与人做的选择。迭代案例展示“为什么改、改了什么、是否解决”，不是堆版本号或做工具使用教学。
- 先看用户给的真实材料和代码，再作产品判断；不把演示结果说成正式发布或验证成功。
- 故事之间用一句可直接读出的短转场。不要每次重新自我介绍；不要重复同一个市场比较或验收清单来填时间。
- 非母语演讲者优先常用词、短句、主动语态。把 native-sounding 长句拆成可一口说完的句子。保留用户的自然语气，不擅自变成课堂互动；需要互动先沿用明确约定。
- 技术抽象用可见变化表达：build 时间很长用长条表示；试错更便宜用短步和闭合循环表示；AI 的价值用“反馈 → 查找 → 行动 → 检查”表示。循环必须有返回路径，动画只强化顺序。

## 一份内容，两个视图

| 内容 | 观众投影 | 演讲者讲稿 |
|---|---|---|
| 主张 | 大标题，一眼看懂 | 用短句展开 |
| 例子 | 一张图/一个流程/几组关键词 | 必要上下文和为什么 care |
| 操作 | 无需演讲者逐个点击 | 中文黄色【动作】放在对应口播之前 |
| 来源/范围 | 必要时简短脚注 | 非口播提醒单独放，不能让人误读 |
| 时间 | 不显示工具栏 | 总用时、本页用时、预算与估算分开 |

默认英文演讲正文、中文舞台提示，实际语言遵循用户。`say` 必须是要讲的话；`cue` 只放停顿、指向、翻页、播放和可选分支提示。不要把 “This is only an example…” 之类内部免责声明塞进正文，除非听众真的需要听到它。

## 视觉系统

- 深森林绿 `#101e19`、暖纸色 `#f0ecdf` 交替；主文字 `#173c2c`，薄荷绿 `#c5edca`，少量珊瑚色 `#f0a684`。
- DM Sans 主标题 + Libre Caslon Display 的强调行；DM Mono 用于页码、小标签。CSS 带系统字体 fallback；网络字体加载失败不应阻止演讲。
- 桌面标题约 68–104px，正文关键词约 28–36px；先删字和拆页，不靠缩小字体塞满。
- 宽留白、巨大标题、细线连接和少量色块；不堆装饰卡片、图标和密集 bullet 列表。
- 一屏一个重点。图、字幕、二维码以投影可读为准；二维码留足白边，扫码目标文字可见。真实 logo/QR 由用户提供或按明确目标生成，不随模板传播。
- 演讲者页以绿色大字口播为主，小缩略图辅助定位。桌面两栏按左后右；窄屏改为单栏，溢出时可滚动，不能裁掉句子。
- 翻页 smooth scroll 与内容淡入保留；远程切页也走相同路径。不要让远程切页退化成瞬移。尊重 reduced-motion，缩略图静态可见。

## 时长与最后阶段

- 模板的估算只统计英文 `say`；中文 cue 不计词。按 100–120 英文词/分钟是显式假设，不是对每位演讲者的测量。
- 视频单独计时，Q&A 单独留时间；一页的预算不能证明口播能讲满。正式标注依彩排修订。
- 最后阶段只改用户指出的内容。删重复页时同步生成页码、缩略图、转场和目录；不要顺手增加新章节、改其余故事、重做整体 UI。
