# 交付验证：保留风格，验证实际演讲路径

修改现有演讲时，只验证/修正授权范围；不把本清单当作改版理由。单页文字小改不需要重跑全部流程。runtime、版式或媒体变更才需要对应的行为检查。

## 两类内容检查

1. 对照已认可的代表页与 `authoring.md`，检查文字量、字体层级、配色、生活物件插图调性、留白、流程箭头和动画含义。大面积留白是设计选择，不能用空白像素比例自动判失败。
2. 按 `speechwriting.md` 回读主线与完整口播，逐页记录重复、上下文缺失、图文顺序不一致或转场跳跃。投影与讲稿各自承担不同信息量，不能要求图上补齐所有解释。独立模型审阅不能证明真人听懂了。

## 实际输出的浏览器证据

从最后交付的目录启动本地服务，不只验证源文件。按 `presenter.md` 检查双窗口，再对每个稳定 slide ID 保存截图，记录浏览器、窗口大小和字体加载状态。桌面至少 1280×720；需要时覆盖现场 16:10/4:3，讲稿另查窄屏可读性。检查裁切、碰撞、过小文字和图表的单位/含义。连续动画应在可读状态截图，缩略图/reduced-motion 应静态可读。

可用包内可选测试（需已安装 Playwright 与 Chromium；不向演讲输出引入依赖）：

```bash
node <skill-dir>/scripts/test_browser.cjs http://127.0.0.1:8765 /tmp/presentation-evidence
```

若使用已安装的 Chrome，可在命令前设置 `PLAYWRIGHT_CHANNEL=chrome`；Playwright 模块须在 Node 的解析路径中。

它针对模板示例验证双窗、彩排记录、导出、暂停/回访/刷新/重置、窄屏，并保存每页截图。执行前先构建 `assets/template/deck.json`。自定义 deck 的内容、视频、可访问性仍按实际材料检查；不要为通过示例测试改动用户内容。

自动测试与截图互补。参照 [Playwright 截图比较](https://playwright.dev/docs/test-snapshots) 的限制，不在字体/OS/浏览器不同的环境承诺逐像素相同，也不用粗略亮度或空白率当设计质量分。

## 彩排、离线与交付

- 真人用实际 notes 布局和按键讲一遍；结束暂停并导出记录。对比逐页实测与预算，记录卡词、跳题和可删内容。未做人声彩排就写未测。
- 在复制后的交付目录冷启动，断网/禁用缓存后查本地素材、字体 fallback 和媒体，不能仅因文件在本机就声称离线可用。网络字体失败可接受，但回退字体必须仍可读。
- 若要公开分享，检查发布文件集，避免带上私人 notes、cue、彩排记录或群邀请。观众阅读页与 PDF 仅按需求生成；阅读页可补必要解释但不改变投影密度。PDF 要验证页数和动画最终状态；不能承诺保留视频和动画。
- 远程会议和实体扩展屏分开测：远程只分享观众窗口/标签页，从接收端确认画面及视频声音。浏览器打开正确不等于投影布置或会议音频已通过。

## 简短验收记录

交付证据放在演讲输出旁的报告，不塞进投影或口播：

| 检查 | 环境/入口 | 结果与证据 | 未测/限制 |
|---|---|---|---|
| 风格与逐页渲染 | 浏览器、分辨率 | 截图目录、具体页 ID | 字体/屏幕差异 |
| 连贯性与口播 | 听众及材料 | 修正的页与原因 | 是否有真人 |
| 联动与计时 | notes 打开真实 popup | 测试结果/导出记录 | 实体屏是否已测 |
| 媒体/离线/分发 | 最终目录 | 实际检查 | 未测试项明确列出 |

观察到故障后只改相关部分，再测受影响路径；不要顺手添加新主题、控制台或配置系统。
