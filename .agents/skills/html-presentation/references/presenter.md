# 现场操作和同步实现

## 一台电脑、两块屏幕

1. 用 HTTP/HTTPS 打开 `notes.html`，不要 `file://`。localhost 可以；另一块屏幕是同一台电脑的扩展显示器，不是另一台电脑。
2. 将系统显示方式设为扩展，而不是镜像。在讲稿点击“打开演示窗口”，拖新窗口到投影屏。
3. 在投影窗点一次“准备投影”：尝试 Fullscreen API，并在存在视频时解锁媒体播放。浏览器可能拒绝全屏/有声播放，按状态提示在演示窗口手动处理。全屏必须有用户手势，不能承诺远程键盘自动绕过浏览器限制。
4. 回到笔记窗口，用 ↑↓ / Page Up / Page Down 切页，Home / End 到首尾。演示窗也支持 ←→ 和空格；需要同步时以 notes 为主控，投影窗本地操作不会反向控制讲稿。
5. `T` 同时开始/暂停两个时钟；“全部重置”清零。总计时连续，本页计时每次进入不同页重新开始，回到上一页也重新计本页。暂停时翻页不启动计时。重载同一标签页恢复时钟；运行中的时钟把刷新期间的时间也算进去。
6. 视频页 `V` 播放/暂停，`R` 重播；离开视频页自动暂停。没有视频也能正常切页、同步和全屏。

## 同步合同

- notes 建立 `crypto.randomUUID()` 的 session，保存到同一标签的 sessionStorage。两页用 `data-deck-id` + 所在路径隔离不同演讲，再加 session 隔离不同演讲者窗口。
- 讲稿通过 `window.open(index.html?presenter=<session>#<id>)` 打开投影。两边使用同名 `BroadcastChannel`。要求相同 origin、浏览器配置文件、设备；它不是跨设备同步服务。
- `slide {id}` 是指令；稳定语义 ID 是身份，页码只是显示。投影收到后调用与本地键盘相同的 `go()`，保留动画和 reduced-motion。
- `ready` / `hello` 建立连接；`ping` / `state` 每 2 秒更新存活状态和视频状态。投影刷新后发 ready，notes 重发当前页；6.5 秒未响应标为断开。重新打开按钮复用命名窗口。
- `video {action: toggle|restart}` 只控制 video 页；反馈携带 playing、blocked、fullscreenFailed。展示操作失败提示，不假装播放成功。
- `navigationUntil` 屏蔽 smooth scroll 经过中间页时的 scroll 事件，避免同步动画被打断。缩放/resize 对齐当前页，不触发额外换页。
- 模板从数据生成 `data-budget-seconds`，支持 30 秒等非整分钟预算。计时器不能从人类阅读的时间文本解析预算。

## 浏览器验收清单

- 在真实输出目录打开 notes：一页一段讲稿、黄色 cue、正确的小缩略图；英文无裁切。
- 点击按钮打开投影：同 ID，连接状态成功；↓ 两边前进一页，↑ 返回；smooth scroll 保留；快速按键不乱序。
- T 开始，等数秒：两个时钟增加；切页总计时不归零、本页归零；T 暂停后两者停止；刷新保持暂停和数值；重置两者归零。
- 投影刷新后恢复当前讲稿页；关闭投影后出现断开；重新打开后恢复同步。
- 第二套独立 notes session 不控制第一套投影；不同 deck/path 不串台。
- 有视频时确认首播、暂停、重播、离页暂停和受限媒体提示。没有媒体时也检查 runtime 无空引用。
- 用投影实际分辨率检查；模板至少用约 1280×720 桌面检查两页，窄屏检查单栏或滚动 fallback。检查 reduced-motion 不出现强制循环动画。

脚本校验、静态截图、单页打开都不能替代双窗口行为检查。实体投影屏位置与浏览器全屏限制由现场复核。
