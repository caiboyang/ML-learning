# 通用口播方法：从一个主题到能讲出来的话

适用于新演讲和用户授权的内容重写。小改某一句时只用相关原则，不重新设计全篇。目标是让听众跟上并带走一个有用判断，不是把屏幕文字扩写成长文章，也不是把任何主题包装成 AI、创业或个人故事。

## 1. 先把“我要讲什么”改写成“听众需要理解什么”

用已有材料完成四句简短的备课判断，不把它们原样念出来：

- 听众正在面对什么具体处境？他们已经知道什么，缺少什么上下文？
- 听完后，他们应该更能理解、判断或完成什么？知识介绍也可以以“能解释为什么”为目标，不必强行变成行动号召。
- 他们为什么可能不在意、不相信或误解这个主题？这是推断还是已有反馈？
- 演讲者有什么实际经验、证据或职责能帮助他们？没有给出的身份、成绩、亲历和团队贡献不能编。

听众名称只是线索，不是需求结论。“MBA 学生”不能自动等于“都想创业”，“管理者”也不等于“只关心成本”。把未知当作假设；只有会改变主线且现有上下文无法回答的问题才向用户确认。

将结果压成一句备课主张，例如：“让第一次管理项目的人明白，交付速度变快以后，验收标准反而要更早说清。”它比“介绍项目管理趋势”更能决定哪些材料该留。主张不够证据支持时收窄范围，不靠更强烈的措辞补足。

## 2. 按理解障碍选切入口，不强制同一种开场

| 听众的主要障碍 | 可选切入口 | 随后必须交代 |
|---|---|---|
| 不知道为什么与自己有关 | 一个他们熟悉的任务、麻烦或机会 | 这个主题怎样改变该任务 |
| 面对多个选项，不知道怎么选 | 一个具体取舍 | 判断标准和证据 |
| 概念太抽象 | 一个可见的输入、过程、结果 | 机制为什么产生这个结果 |
| 已有直觉与事实冲突 | 一个有依据的前后差异或反常结果 | 条件和原因，避免用噱头代替解释 |
| 想知道这段经历有什么意义 | 经历中真正困难的决定 | 为什么这样选，以及听众能借用什么 |

这是选择菜单，不是必须逐项经过的流程。若用户已指定切入口，先把它与听众连起来，不擅自换故事。若是汇报紧急结果，先讲结果和影响，不先铺故事。

开场通常几句就够：熟悉的处境 → 尚未解决的疑问/取舍 → 今天能得到的理解。先让听众有理由听，再介绍案例。主持人已经介绍身份时不再重复；无需在每个案例重新报姓名。

“听众心里的问题”不等于现场提问。没有互动安排时，用陈述句承接；不要写“举手”“谁来分享”或等待回应。

不同领域的短开场示例（写法示意，不是事实依据）：

- 经营实验：`A new lunch offer may bring in more people. But will it leave the café with more money? We can test that before changing the whole menu.`
- 隐私培训：`You need to send a file to a partner. It also contains customer details. Before you share it, you need to know what they actually need.`
- 技术原理：`You open the same page twice. The second visit feels faster. Let's look at what the system kept, and when that copy can become out of date.`

它们分别从取舍、工作场景、可观察现象进入，没有硬套个人经历或“未来趋势”。

## 3. 先写论证主线，再分屏

把主线写成少量相连的判断，而不是章节名列表。检查每个连接：为什么上一点成立之后，听众会需要下一点？

例如，“方案看起来不错 → 但销售额不代表赚得更多 → 因此先约定检查什么 → 再用一次小实验收集证据”。比“背景 / 数据 / 方法 / 总结”更能产生自然转场。

给每屏留下四个备课字段，可放在草稿中，不需要增加 deck.json 字段：

1. **这一屏的作用**：听众应多理解哪一件事？
2. **支撑它的材料**：具体场景、真实证据、必要对比或明确标注的假设例子。
3. **它的意义**：为什么这个材料支持主张，适用到哪里？
4. **下一步的理由**：还缺哪个问题，所以下一屏讲什么？

不是每页都需要新的例子。承接页可能只有一句，数据页可能需要更长解释；同一例子可推进新判断，但不要重复完整背景。类比只解释结构，不能充当事实证据。

## 4. 将备课判断写成完整口播

先写能连续讲的 `say`，再提炼投影的大标题和图。不要只放两个提纲词，再默认演讲者会补出一分钟内容。

常用展开是：“说清这一点 → 展示一个具体情境 → 解释你看到了什么 → 说明对听众的意义”。按需要取用，不必每页四段。每个抽象名词至少在第一次出现时落到人、动作或结果上。

例如，“降低决策风险”不能单独承担解释。可以说：

`Before changing the whole menu, try one lunch offer for a week. Keep the rest of the menu the same. Then check the extra sales and the extra cost. This gives the owner a smaller decision to make first.`

讲述案例时区分“发生了什么”“我们怎么理解”“我们做了什么选择”。不把猜测写成确定原因，不把一次结果写成普遍规律。团队做的事用 we，明确属于个人的体验才用 I。

转场写成可以直接读的一句因果、取舍或未解决的问题，而非机械的 `Now let's move to the next slide.` 例如：`But more sales do not always mean more money. So we need to decide what to measure.` 如果和刚讲过的结尾重复，只留一句。

屏幕展示流程或对比时，口播按同一顺序展开。先引入未见过的产品或缩写；只给理解当前论点所需的上下文，不展开产品手册。

## 5. 写成这个演讲者说得出的话

- 非母语英语优先短句、常用动词和明确主语。一句通常只推进一个意思；不能为了机械字数把自然句子切碎。
- 用能说出来的说法代替压缩的书面名词。例如 `check the result` 往往比 `conduct outcome verification` 易讲。必要术语第一次解释，不把全部语言幼儿化。
- 不替用户发明口头禅或夸张情绪。保留用户指定的兴奋、幽默或个人语气，但修正明显语法问题和没有依据的宣称。
- 去掉多层从句、连续三个抽象词、指代不明的 it/this、括号里的插话。数字优先讲数量级或差异，精确值留在确有必要的地方。
- 正文必须包含实际要讲的解释。`这里展开一分钟` 不是完成的口播；`[举一个例子]` 也不能留给临场补。
- 动作、停顿、播放和翻页放入 `cue`，出现在相关动作之前。不要把内部事实核查提醒当成正文；听众确实需要知道的假设与范围则应直接说清。

## 6. 用篇幅与朗读校准时间

先按 100–120 英文词/分钟估算，再单列媒体与真正需要的停顿。这只是起点，不能保证具体演讲者的速度。5 分钟纯英文口播通常需要约 500–600 个词；不是给五张短句页各写“1 分钟”就成立。

如果讲稿明显短于目标：先判断是否缺少必要的例子、推理或听众意义。缺了就补；没有缺口就诚实缩短预计时间或讨论调整目标，不加背景废话，也不要求用户拖慢。超时则先删重复、次要分支和不服务主线的细节。

检查或朗读每页开头、结尾及相邻转场：能否一口接上，是否突然换主题，是否出现只能在文档里读懂的句子。最终以演讲者实际彩排修订。没有真人朗读时明确“已做文字/时长检查，未做口头彩排”。

## 交付前的内容验收

- 听众能在开场理解“为什么要听”，而不只知道演讲者做了什么。
- 每个观点有足够支撑；情境、证据、推断与适用范围没有混淆。
- 读 `say` 就能讲完必要内容；读者不必自行发明案例或补齐逻辑。
- 新的对象、缩写、界面和版本已有最低限度上下文；讲解顺序与投影一致。
- 转场解释下一点为什么出现；重复例子只保留有新作用的部分。
- 语气、身份、互动安排与用户一致；时间估算不冒充实测。

这套方法帮助选内容与组织语言。只有用户要生成网页演示时才走构建和发布流程；口播修改不自动授权重做 UI、添章节或部署。
