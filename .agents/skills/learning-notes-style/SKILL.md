# 学习笔记的行文与视觉风格

使用本文件和随附资源复现风格，不需要寻找某个仓库的相邻页面。它负责怎么写、怎么呈现；研究和教学顺序由调用方提供。用户明确指定其他风格或格式时，以用户要求为准。

## 使用入口

- **Markdown 笔记或参考手册**：应用下方行文、信息层级与 Markdown 规则，不为配色擅自生成网站。
- **HTML 学习页**：先读下方规则，再读取并复制 [assets/learning-page.html](assets/learning-page.html) 到交付目录，替换示范内容。文件自带 CSS、语义化组件和内联结构图，没有构建步骤、Jekyll frontmatter、外部脚本、字体下载或仓库链接。
- 相对资源路径始终以本 `SKILL.md` 所在目录解析。复制本 skill 时保留完整文件夹；可独立使用，不依赖 `learning-notes` 或原始专题。

模板里的两章只展示排版，不是课程长度要求。替换标题、读者前提、目标、全部教学内容、图注与来源；删除不适用的组件，按实际大纲增减章节。不要把“样式示范”当成完成的学习笔记。

## 行文：清晰的技术讲解

- 开头直接给研究对象、读者前提、学完能做什么。用一个核心问题串起后文，不写通用行业背景充篇幅。
- 一段推进一个意思，通常 2–4 句；句子尽量包含主体、动作和对象。先说实际行为，再给术语与源码符号。
- 结论之后紧接依据、案例和适用条件。主线保留足够理解下一节的内容，较长推导、源码逐行解释与自测答案可展开。
- 用粗体强调每段最需要记住的关系或判断，避免整段加粗、连续警告框、每句都加标签。
- 术语首次出现给中文解释和必要的英文名，此后用一致称呼。精确字段、函数名和示例值使用行内代码。
- 类比就近说明对应关系和边界。工程实现对照使用具体名称与证据，不用夸张比喻、人格标签或“多数系统都这样”制造直觉。
- 来源紧跟所支持的论断、图或表，以可读标题链接到具体位置。事实、解释、建议可用简短标签区分，避免长串裸 URL 打断阅读。

例如，把“系统通过高效机制实现了上下文的智能管理”改成“工具返回后，程序把结果追加到活跃历史。下一次构造模型请求时，再从这份历史选取输入”。后一句只有经研究确认后才能用于具体产品。

## 页面风格：深色阅读底，图解分层

以连续的文章阅读为主体，章节用留白与细线分开；卡片只承载并列项、局部结构或交互。不把整篇文章切成仪表盘，也不添加与理解无关的动效、图标和大面积渐变。

### 色彩与语义

以下 token 是默认值，也写在 HTML 起点中。背景可有很淡的点阵；正文区域保持安静。

| Token | 值 | 用途 |
|---|---|---|
| `--void` | `#07090F` | 页面底色 |
| `--night` | `#0E1320` | 首屏、目录、代码和展开区 |
| `--surface` | `#141A2A` | 局部结构与提示面板 |
| `--rule` | `#232C44` | 分隔线与普通边框 |
| `--paper` | `#E8E5DD` | 主文字 |
| `--paper-dim` | `#B6B2A6` | 说明文字 |
| `--paper-muted` | `#A39C92` | 图注与元信息；不可用于禁用关键内容 |
| `--phosphor` / `--phosphor-glow` | `#7BE3D7` / `#A7F2EA` | 链接、当前项、重点与键盘焦点 |
| `--amber` | `#FFB57A` | 设计取舍、条件与代价 |
| `--rose` | `#FF8FA3` | 反例与失败点 |
| `--diagram-paper` / `--diagram-ink` | `#F5F5F0` / `#222222` | 复杂结构图的浅底和深字 |

色彩必须伴随文字或形状说明。图区可在浅底中保留浅青色模块，不要把深色正文中的浅字直接搬进浅底图。

### 字体、尺寸与节奏

| 元素 | 默认规则 |
|---|---|
| 正文 | `Newsreader, Noto Serif SC, Songti SC, STSong, serif`；19px / 1.78，窄屏 18px |
| 标题 | `Inter Tight, Noto Sans SC, PingFang SC, system-ui, sans-serif`；H1 为 `clamp(36px, 6vw, 66px)` / 1.15；章标题 28–30px / 1.35 |
| 目录、表格、图注、控件 | `Inter, Noto Sans SC, PingFang SC, system-ui, sans-serif`；正文辅助区 15px，表格 14px，图注 13px |
| 编号、字段、代码 | `JetBrains Mono, SFMono-Regular, Consolas, monospace`；编号 12px，代码块 13px / 1.8 |
| 阅读宽度 | 主容器上限 836px，左右内边距 28px；首屏内容上限 880px |
| 首屏与章节 | 首屏内边距 84px 28px 56px；章节间距约 76px；段后 20px，图表前后约 26–28px |
| 面板 | 内边距 18–24px，1px 细边框，8–10px 圆角；不叠加厚阴影 |
| 窄屏 | 640px 以下左右内边距 22px，首屏 60px 22px 36px，章标题 25px，目录与并列内容改为单列 |

字体栈自带本机回退，未安装首选字体时也应可读；不依赖联网下载才能显示。若交付需要跨机器一致的字形，可在许可允许时随产物附字体并用本地 `@font-face`，不承诺仅靠字体栈实现像素一致。

## 信息层级与组件用法

1. **首屏**：主题标识、准确的标题、一段导读；元信息展示读者前提、学习结果、证据范围及已有的配套入口。没有配套材料就删掉该项，不生成假链接。
2. **学习地图和目录**：一句主线，接带问题描述的有序章节入口；桌面可双列、手机单列。正文顺序与目录一致。
3. **章入口**：连续编号、问题式标题、可完成的学习结果；长章再给局部导航。
4. **机制讲解**：先用短结论定位问题，接图、具体数据或案例，再解释变化与原因。图注说明画的是什么、读图顺序、简化条件和证据。
5. **局部补充**：青色左线用于关键结论；琥珀色左线用于取舍；玫红色左线用于反例。提示框用明确标题说明含义。
6. **深入与自测**：原生 `details/summary`；summary 直接说“展开源码推导”或“查看答案与推理”。读者先看到题目，答案折叠；关键前提始终可见。
7. **章末**：一句承接下章的问题，加“继续”锚点。文末回到整体，附需要的参考入口。

按内容需要选用组件，不能机械地每节全部插入。表格适合比较，图适合关系和变化；不要把长段文字塞入每个表格单元或图节点。

## 图表、交互与可访问性

- 结构图使用有序容器或 SVG；时序与状态图可用 Mermaid。给图提供文字解释和图注，不让外部渲染库失败时只剩空白。
- 输入布局与状态图保留对象标识、顺序、类别和可见性边界；同一对象跨图沿用名称和颜色。视觉分组与真实字段不是同一层时明确标注。
- 代码块、宽表与宽图在各自容器内滚动，不让整页横向溢出。滚动区有可见说明、可访问名称与键盘焦点；手机优先展示当前要理解的对象。
- 链接保留下划线，交互元素有青色焦点轮廓。控件使用原生元素和明确标签；状态切换同时更新可见说明和相应 ARIA 状态。
- 不自动播放、不强制动画推进课程，尊重 `prefers-reduced-motion`。JavaScript 或网络不可用时，核心文字、默认图和目录仍可读。

## Markdown 与参考手册

保留同样的教学层级：准确标题 → 读者前提和目标 → 主线目录 → 连贯章节 → 证据和深入入口。使用标准标题、短段落、比较表、带语言标记的代码块、图注和描述性来源链接；短文省去多余导航。

核心图可用 Mermaid、独立 SVG 或有序文本剖面，按目标渲染器选择。只有确认渲染器支持时才使用 HTML 展开区；否则改成普通小节或附录。Markdown 的主题颜色由阅读器控制，不能声称纯 Markdown 能强制复现 HTML 配色。

## 脱离仓库的验收

仅复制本 skill 和它的 `assets/` 到一个空目录，复制 HTML 起点并打开：在 1280px 与 390px 宽度检查文字、图、目录、表格和展开区。确认没有原仓库路径、主题、构建工具、字体服务或外部脚本依赖；离线仍有完整内容。

实际交付前检查新增链接、锚点、长标识、键盘操作与横向滚动，阅读截图确认层级和密度。把可复现的 token、结构与交互作为验收依据，字体回退造成的字形差异单独说明。
