# 公司研究深度与问答合同

## 适用方式与深度标准

此文件是 Agent 执行完整公司调研时的独立验收依据，适用于不同公司的商业模式、产品策略、竞争和创业路径研究。按具体业务与研究目的判断各模块是否适用。

研究深度由四项能力决定：用具体事实描述业务，解释价值与资金如何流动，比较关键阶段的选择及结果，把结论转化为有条件的决策和验证。篇幅、公司数量、评分和视觉复杂度不能替代这些能力。历史归属、因果判断和迁移建议均需独立核实。

执行顺序见 [Skill](../SKILL.md)。本文件集中维护研究判据、案例深度、问答更新与内容验收；展示和字段分别链接到专门参考文件。

## 完整研究的覆盖与验收

每个适用模块需要有**具体对象或事件、来源证据、机制解释、决策含义、关键未知**。数据不足可以限制结论强度，但不能用通用商业常识填满空白。标记不适用时说明与当前业务或研究目的的关系。

| 模块 | 需要深入到什么程度 | 可检查的产物 |
| --- | --- | --- |
| 研究目的与公司阶段 | 明确在研究哪项业务、哪个时期；分开已证明、有信号、未知和反证 | 任务范围、阶段判断、主要约束及其依据 |
| 客户与市场 | 明确使用者、付款者、决策者、购买触发、原有替代、预算和不购买原因；市场估计与实际可触达需求分开 | ICP、具体购买场景、需求证据、市场口径 |
| 产品与交付 | 对每项主要产品查客户、承诺、价格或收入单位、真实流程、人工参与和结果；区分已交付、活动验证、原型、计划与持续供给；按支持当前命题的验证强度排序 | 有证据与状态的产品组合表、主要收费／入口／工具／下一验证方向的组合判断、交付与成本边界 |
| 渠道与成交 | 区分公司、创始人、合作方、推荐等渠道；查触达、信任、转化、耗时、归因和关系归属；区分主渠道、转化页、放大器、品牌说明、信用背书及缺口 | 渠道角色与线索流向表、当前取舍与来源记录要求、可核实漏斗、拒绝与流失原因 |
| 资源与组织 | 每人列角色、背景、实际职责及证据；查资源控制者、承诺、期限、容量和替代性，区分实际分工与拟议安排 | 团队与分工表、负责人清单（未知或待确认单列）、资源承诺与关键依赖 |
| 收入与经营可持续性 | 查收费方式、付款证据、交付与支持成本、获客实施投入、现金要求、复购留存；不公开则保留缺口 | 单位经济或有标注的情景模型、敏感变量 |
| 创立与早期路径 | 查创始人起点、第一批客户、初始产品、第一次商业验证、人工服务、产品化与扩张的实际动作 | 带日期和来源的“约束—动作—结果—变化”路径 |
| 融资及外部资源 | 适用时查资金、资助或伙伴在什么阶段支持了什么；分开轮次金额、累计融资和业务收入 | 融资与经营里程碑对应、投资理由的证据边界 |
| 增长与竞争 | 解释续用、转介绍、供给扩张、成本改善的反馈；比较人工、替代产品、内部开发和不行动；写优势失效条件 | 有证据状态的反馈图、替代矩阵与约束 |
| 机制对标 | 选择与当前问题相关的公司和阶段；重点对象深入到与目标公司可比较，解释为何能或不能借鉴 | 冷启动资产矩阵、四模块重点案例、分阶段迁移表及反例 |
| 既有建议与路线选择 | 有既有建议时审查适用性；有决策任务时比较可行路线，说明机会成本、先后顺序和暂缓原因 | 当前主路线、四道门槛、会议确认类型、改变选择的证据 |
| 验证与行动 | 从重要未知推导调查或试验；确定指标口径、资源、责任角色、时间窗和判定标准 | 分阶段计划、经营数据合同、待确认责任、继续或停止条件 |
| 证据与未决问题 | 关键论断能回到直接来源；公开资料、用户回答、推断、情景分开；保留冲突和不确定性 | 证据台账、问答记录、缺口与结论覆盖表 |
| 结果组织与呈现 | 摘要、业务解释、横向比较、行动和证据有明确分工；图表形式与判断任务匹配；重要数字能追证 | 研究覆盖、具体议题目录、图表与版式计划、交互及展示验收 |

对标数量由要比较的机制决定。涉及借鉴别家路径时至少选择一家重点案例；其他对标按需要增减，选择与缺口规则见下方案例合同。若只分析一家，应足以回答所选问题，并说明其他机制未覆盖。不得用若干公司简介替代重点对标的早期路径和结果证据。

每家进入横向矩阵的公司都按同一顺序拆解：一句话结论 → 起点与切入点 → 带时期的关键动作与结果 → 增长反馈 → 可迁移／不可迁移 → 风险与直接来源。重点案例进一步展开四模块；其他公司也不能只留矩阵一行。证据缺失写已查范围及结论影响，不补写标准创业故事。

资源和团队模块在外部公司分析中可能只能核实公开信息。不要将“未找到固定投入证据”写成“没有投入”，或要求用户提供其无法获得的内部信息。

分析覆盖表不直接等同于展示目录。先按 [结果组织与呈现规范](result-presentation.md) 建立阅读路径，再把各角度的事实和判断放入合适模块；一项判断应有主要位置，其他位置通过摘要和引用连接。

## 已授权内部记录的取证与复算

先盘点任务已授权可读的系统、表和记录范围，再列现有字段、标识、事件、时间窗与可计算指标。能从记录复算的先自己算，不把它们转成问卷；没有授权或访问能力时记录该边界，不自行扩大权限。

按业务重建同批数据：进入、首次有效行为、分期持续使用、成果、再次使用或付款、转为供给方以及新老用户构成。具体事件和周期随业务调整，不机械套用每周出勤。保留去重键、分子分母、筛选、时区、读取范围、核对日期和计算方法；观察窗未满、记录缺失与零值分开，复用和转供给分支的交集单列。

现有记录不自动等于可靠口径。核对事件含义、覆盖期、重复记录及系统之间的映射；与用户叙述冲突时先检查时期和范围。报告只输出决策所需的汇总和脱敏证据位置，不附姓名、联系方式或个人原始明细。价格、付款等信息若在授权记录中可核对，同样先查，不预设为只能问用户。

## 证明命题随业务改变

| 业务类型 | 常见证明命题 | 必须避免的替代 |
| --- | --- | --- |
| 付费服务 | 交付、付款、成果、持续使用、复购、供给复制 | 出席不等于成果，意向不等于付款 |
| 消费社交／免费社区 | 激活、同批留存、回访频率、内容沉淀、创作者留存、变现条件 | 下载不等于活跃，总活跃不等于同批留存 |
| 企业软件 | 部署、使用深度、客户结果、续约、净扩张、实施与支持成本 | 签约额不等于确认收入，席位不等于使用 |
| 双边平台 | 两侧激活、有效匹配、履约、重复交易、两侧留存、单位经济 | 供给名单不等于可交易供给，交易额不等于收入 |

注册不等于付款，交易额不等于公司收入，融资不等于客户收入，接触资源不等于可支配资源。

按具体业务替换命题并解释。状态为已证明、有信号、未证明、反证、不适用；不适用必须有理由，不因尚未获得数据就排除重要命题。免费产品的用户重复付款可能不适用，长期变现与经营可持续性仍需分析。

## 关键决策复盘与衰退诊断

外部公司研究应独立呈现关键转折：发生时间、当时约束、当时可知信息、备选与证据身份、实际选择、之后观察到的结果、机会成本与未知、研究者解释、会推翻解释的证据。未获内部资料时，不把研究者提出的备选写成管理层讨论；没有公开理由时保留未知。选择后的结果不等于选择导致的结果。

对爆发后放缓、衰退或转型，分别检验环境与需求变化、竞争复制或分发替代、产品自身反馈中断。每种写作用机制、时序和可比数据、支持证据、反证及还需取得的区分证据。三者可并存，不强选唯一原因；无法区分时交付有条件的解释排序。下载、总活跃、同批留存、创作者供给不能混为一条趋势。

统计聚合站只作发现线索，不把其无可追溯来源的数字用于现状或趋势结论。核对到原始披露或公开定义、样本与方法的原始测量后，引用底层来源并保留边界；多站转载同一个数字不构成多份独立证据。

## 重点公司专题的最低结构

完整任务涉及借鉴别家路径时（自有业务选路线，或外部研究给借鉴顺序），至少深入一家重点对标。优先选择起点资产与阶段最接近当前候选路线的公司，写明选它、未选其他对象的理由；路线未定时依据所检验的机制选择，再用研究结果修正路线，避免循环证明。主页面独立一节呈现其完整关键步骤，四模块论证进入子页。外部研究中，目标公司自身路径也按下面四模块拆解。

材料不足时不编造步骤，也不静默跳过：在覆盖清单的“重点案例”项标“关键缺口”，写候选对象、已查范围、缺少什么及对迁移判断的影响。用户明确缩小范围或任务不涉及路径借鉴时，可标不适用并说明原因；不能把省略工作写成不适用。

首屏给公司、分析时期、一句话机制判断和证据边界；基础档案并列起点资产、第一批用户、第一个产品、第一种收入、扩张或融资依据。融资原因缺直接材料时标为推断。下面四块应能独立讲清，不埋在一段公司简介里。

| 模块 | 要拆到的动作 | 展示产物 |
| --- | --- | --- |
| 互补起点资产 | 哪项资源解决供给、分发、专业知识、交付或工程瓶颈；谁控制；各资源怎样配合；当时已有什么、仍缺什么 | 资产—作用—实际投入—证据表，连接首批客户或供给 |
| 首次交易与交付验证 | 怎样找到首批用户、理解阻力、收费、交付、收反馈；若曾人工服务，拆人工动作、成本与何时适合产品化；未见证据则说明 | 带阶段标签的动作卡，每步分开事实、结果和机制判断 |
| 取舍与反模式 | 有来源的主动不做、失败尝试及机会成本；另列分析者推导的避坑建议 | “已证实取舍／分析建议／未知”三种证据身份，避免从沉默推导克制 |
| 回路与迁移 | 上一轮产出如何改善下一轮供给、分发、结果或成本；哪些边已观察；目标业务拥有哪几环 | 有证据状态的回路图＋可复制／不可复制条件 |

步骤数随证据增减，不要求固定六步。阶段标签可以是洞察、团队、切入点、人工验证、收入证明、产品化、扩张，也可以用适合该业务的标签；并行阶段不得被画成虚构的严格先后。案例本身不是成功方法的证明，应检查不同起点或失败样本。

横向矩阵使用相同字段：公司与阶段、起点资产、第一批用户、最初产品、收入证明、扩张依赖、目标业务资产差距、当前可学动作。相似度没有定义时用文字判断，不造精确分数。

## 迁移、决策门槛与会议摘要

有用户业务决策任务时，先收集已有方案、顾问建议或团队正在考虑的动作；未提供且会影响任务时询问，不要求正式文档。比较真实可行的备选、资产差距与机会成本，推荐一个当前主路线；证据不足时给暂定路线及决定分歧的最小验证。早期验证聚焦一类优先客户、一个主要承诺和一个结果标准，不把单一产品要求套到成熟多业务公司。既有建议按立即采用、带条件采用、明确删除复盘，无法判断的另列待确认。纯外部研究交付借鉴条件与调查，不虚构运营授权。“第二阶段”是当前路线达标后的升级；“备选”是满足切换条件时改走的方案，要写验证截止点、未达标条件与切换动作，不能与“暂缓”混用。

| 迁移分类 | 采用条件 | 必须写明 |
| --- | --- | --- |
| 现在复制 | 阶段相符，关键资产可调用 | 最小动作、观察指标和承载上限 |
| 以后复制 | 有潜力，但缺已知前提 | 先证明什么，何时重新评估 |
| 谨慎借鉴 | 只部分机制适用或外部依赖大 | 保留什么、改掉什么、失败界限 |
| 暂不复制 | 阶段、资源或模式不匹配 | 机会成本和可能重新开启的条件 |

为当前路线安排正式预算与排期前检查四道门槛。门槛用于约束交付承诺和扩大投入；早期试验可以明确测试未知，但不能宣称已经通过重复性验证。

| 门槛 | 判定问题 | 未满足时 |
| --- | --- | --- |
| 可控 | 对外承诺的交付是否在自身能力范围？外部依赖、责任与备选方式是否明确？ | 缩小承诺或先确认依赖；不保证由第三方决定的结果 |
| 可证 | 付款、使用、验收结果或再次购买能否观察？是否有指标、分母、窗口和记录来源？ | 先补测量与验证计划 |
| 可信 | 是否区分实绩、估计、计划、自报与核验？评价真实、数据口径一致且来源可追溯？ | 修正表达和数据；不使用虚假证明 |
| 可重复 | 明确的负责人、时间、成本与容量能否支持多个完整周期？是否仍仅有单人、单客户或单次成功？ | 标为待验证，先跑有边界的重复试验 |

可沉淀资产、扩张成本与单位经济是路线评价维度，不替换上述四项。总工时随业务量增长不自动否定业务；要检查单位利润、人员容量、质量和经营目标。

会议摘要每条使用“决定／依据／条件／确认角色／复盘时间”，再标确认类型：**必须确认**用于资源和优先级选择；**信任底线**用于证据真实性；**产品边界**用于承诺、用户和交付范围；**明确删除**用于排除的动作。它们与“立即采用／带条件采用／明确删除”的建议状态分别记录，不强求互斥，也不固定条数。

## 下一轮经营数据合同

先把主路线转成分阶段计划，默认用 90 天的确定范围、获客验证、交付观察、复盘再售四阶段，周期按业务调整。每段写动作、责任角色或待确认责任、资源、观察指标和继续／停止条件。外部研究改为取证优先级与调查计划，不能只是换标题。

先按[内部取证流程](#已授权内部记录的取证与复算)列出现有系统字段和可复算指标，注明缺失、口径不足或尚未到观察期。下一轮合同只新增缺失或需修正的采集要求；已有可靠字段引用现有记录位置与更新安排，不要求重新填报。

这是一份实际记录约定，不是来源链接表，也不是要求用户一次回答全部问题的问卷。按主路线挑最重要字段，缺失时先问能改变路线的 1–3 项；外部公司拿不到内部记录时交付缺口与代理证据的边界。

| 字段族 | 必须约定的口径 | 影响的判断 |
| --- | --- | --- |
| 唯一对象标识 | 客户／订单／供给方 ID，跨报名、付款、使用和复购去重；分析用脱敏 ID | 是否同一批人或同一笔交易 |
| 实际付款 | 实付人数与金额、币种、折扣、免费、退款、净收款；与会计收入分开 | 是否真有收费、能否回收投入 |
| 分期留存 | 批次、时间起点、活跃事件、退出时间与原因 | 持续使用及流失在哪发生 |
| 成果标准 | 交付前定义验收任务、观察期、实际达标数 | 留到结束是否真的获得价值 |
| 再次付款 | 再参与、再使用、再付款分别记录，标明获得复购机会的窗口 | 使用复用是否变成收入复购 |
| 交付工时 | 组织、实施、支持、复核、返工；人员与成本口径 | 可重复容量、真实单位成本 |
| 渠道来源 | 首触、促成、合作归属、跨渠道去重规则 | 可调用分发与独立获客能力 |
| 窗口活跃 | 定义有效行为、时间窗和独立对象数；30 日仅为常用示例 | 触达人群是否实际使用 |

每个采用字段再填：字段负责人或待确认角色、记录系统与明细位置、更新频率、关联结论、完成期限。比率要保留分子和分母；未知、零、不适用与尚未到观察期分开。平台业务另列供给侧“接触→承诺→首次交付→再次交付”，与用户转化分开；复用和转供给通常是分支，不将有重叠或未知交集的人群串成一个漏斗。

收到数据后按“原判断→新证据及性质→上调／下调／维持→路线和行动变化”记录。先统一同批口径，再更新主报告、专题和图表；内部自报与公开页面冲突时解释时期、范围和核验状态，不能静默覆盖。

## 研究状态与更新方式

在报告草稿中保留简洁研究状态；短任务可内联在正文，复杂任务可放在附录，不必额外创建应用或数据库。

| 记录 | 最少字段 | 更新时机 |
| --- | --- | --- |
| 研究任务 | 对象、业务、目的、时期、交付、范围假设 | 用户补充或调整目标时 |
| 关键主张 | 主张编号、事实内容、来源位置、事件及资料日期、口径、支持边界、反证 | 新资料或用户回答到达时 |
| 未知队列 | 问题编号、影响哪项判断、已查资料、获取方式、优先级、状态 | 每轮研究后 |
| 问答记录 | 问题、回答、回答日期、估计或记录、关联主张、判断变化 | 每次用户回答后 |
| 决策与动作 | 结论、依赖、备选解释、验证、角色、指标、观察窗、停止条件 | 依据变化或试验完成时 |

可以用“已核实”“用户提供”“有信号”“待回答”“仍未知”“不适用”标记研究状态；状态标签后必须能找到具体理由。最终报告中的未决问题只保留会影响判断的部分。

## 怎样提问才有用

先按可获取方式区分未知：公开可查的继续取证；已授权内部记录可得的按[取证与复算](#已授权内部记录的取证与复算)自己计算；只有用户知道的目标、未记录的承诺或意图才少量提问；两边均不可得的保留条件性结论和取得方式。只能靠未来行为回答的设计试验。不要把研究任务转交用户，也不要要求其猜测。

每轮通常 1–3 个高影响问题，每题说明已知背景、缺口、影响的判断及容易回答的口径。允许不知道、不方便或区间回答；无回答不是默认同意。等待时继续无依赖的工作。

例如，用户已有活动参与记录但付款口径不明，可以问：“为判断先验证收费还是扩大获客，最近一批总共有多少人、实际付款多少人、金额与退款各是多少？可以给区间。”这里注册不等于付款，免费与付费人群需要拆开；不能用一个报名总数宣布需求已经证明。

资源问题问已承诺投入和容量，不问泛泛的合作意愿；用途问题只在对话没有明确答案时问；外部公司数据只在用户可能持有时询问。回答记为用户提供，并保留日期、窗口、分母和记录支持强度。

收到回答后按[数据合同中的判断更新格式](#下一轮经营数据合同)处理：核对证据身份，改变受影响的证明状态、资产匹配、对标、迁移分类、主路线、门槛、摘要图表与行动，再决定下一题。不能只把回答追加到附录。没有新证据足以改变判断时写“维持”及原因；用户纠正其自身信息时更新，但保留与公开材料的时期或范围差异。

## 内容覆盖清单：交付时逐项填写

每项写入页面数据的 `coverage[]`：检查对象、状态、关联记录 ID 与缺口；通过记录追到支持证据。状态为“有实质依据／部分完成／关键缺口／不适用”，后三者必须写具体缺口或不适用原因。按[数据约定](dashboard-data.md#覆盖清单数据)校验，并在证据库前完整展示，不受正文筛选隐藏。虚构示例不标成已完成真实取证；不能只勾选“存在组件”。公开资料取不到时写已查范围、对主判断的影响和下一步。单个事实查询不必使用完整报告模板；缩小范围后仍使用模板时保留全部检查项，将范围外项目标不适用并说明原因。

| 检查对象 | 实质验收要求 | 模板落点 |
| --- | --- | --- |
| 任务与证明状态 | 自有决策或外部研究；命题匹配业务，N/A 有理由，结论不超出证据 | meta、首屏、proof |
| 业务、团队与分工 | 产品、客户、渠道、钱与交付连贯；每人角色、背景、责任、承诺与证据；责任未知单列 | assets、team |
| 每家对标 | 逐家公司核对[覆盖与验收](#完整研究的覆盖与验收)中的统一结构，记录具体依据与缺口 | comparisons 专题、profile、step、loop、transfer |
| 重点案例 | 互补资产、交易交付、取舍、回路迁移能独立讲清 | case 四模块 |
| 数据核验 | 自报／核验边界，时间序列保留口径变化与缺失；同批漏斗及分支各自分母；每阶段支持与未支持命题 | audit、series、funnel、proof |
| 判断更新与下一轮记录 | 新证据为何上调／下调／维持，受影响摘要与动作已改；字段、来源、角色、频率与窗口 | change、contract、question |
| 自有业务决策 | 主路线、真实备选、机会成本、采纳状态、四门槛、确认责任、行动与停止条件 | advice、decision 专题、route、meeting、action |
| 外部公司决策 | 关键转折的当时选择与信息、实际动作、后续结果及因果边界；借鉴顺序与下一步调查 | decisions、decision 记录、transfer、调查 action |
| 增长放缓或衰退 | 环境、竞争、自身回路三类解释有证据和反证，不能仅靠前后相关 | 决策复盘或机制章节 |
| 可交付性 | 按专门规范验收主产物完整性、追证、排版与离线交付；不以结构测试代替研究 | [呈现验收](result-presentation.md#展示验收)、[实现验收](dashboard-data.md#验收) |

HTML、schema 与交互通过只代表结构和展示可用。还必须沿一条主判断走到具体动作、数字口径、直接证据和反证，再逐家公司核对覆盖，才能声称完成深入调研。
