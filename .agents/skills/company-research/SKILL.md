# 公司调研执行规范

这份 skill 是给 Agent 执行公司调研使用的工作规范。对完整公司分析，默认深度至少达到 [Stoody GTM Lab](https://stoody-zero-to-one.vercel.app/) 展示的研究层次：从具体业务事实、资源与历史路径，推导机制、可选路线和下一步验证。换一家公司时重新取证，不沿用 Stoody 的结论、教育行业指标或路线推荐。

开始完整调研时读取 [研究深度与问答合同](references/research-contract.md)。其中的覆盖表是交付检查表，问答示例用于处理公开资料无法解决的内部问题。本 skill 与该参考文件一起即可执行；仓库中的公司调研方法报告提供更长的解释、教学案例和模板。

## 1. 确定此次研究要支持的判断

先利用已有对话确定研究对象、具体业务、目的、时间范围和交付格式。区分两种常见任务：

- **理解目标公司**：解释它如何启动、创造价值、成交与增长。用户未必知道它的内部数据，不能把这些问题反复转交用户。
- **为用户自己的业务借鉴经验**：既研究目标公司，也调查用户业务的阶段、资源、客户、已有证据和执行限制。迁移结论依赖这两侧的资料。

用户没明确目的时，可以暂按“理解业务机制与可借鉴经验”推进，并说明假设；若公司身份、业务边界或决策目的存在实质歧义，尽早提出少量问题，同时推进无依赖的资料核对。不要先抛一份长问卷，要求用户完成研究。

## 2. 先查事实，再决定从哪里深挖

读取用户指定材料的正文和关键子页，优先核对官网、产品与定价、产品文档、历史公告、创始人叙述、客户材料及已有授权数据。记录核对日期，区分现状和历史，不只依靠搜索摘要。

默认从一次客户选择切入：**谁在什么触发下，放弃或补充什么旧方案，为哪项结果付出什么成本？** 沿使用者、付款者、购买流程、交付方式和收入成本建立业务全貌。出现流失、成交困难、交付亏损等异常后，再调整调查优先级。

至少检查客户需求、产品价值、起点资源、获客成交、收入成本、留存增长、竞争壁垒、阶段约束八个角度。进一步展开产品组合、渠道归属、资源承诺、团队职责、早期行为、增长反馈和路线选择，具体深度按参考文件验收。

对每个关键命题记录：来源直接支持什么、目前怎样解释、什么其他解释也成立、取得什么证据会改变判断。不要为了填满章节补造事实。

## 3. 把未知分流到取证或问答

每个未知先判断属于哪一类：

| 未知类型 | Agent 的下一步 |
| --- | --- |
| 公开可查，但尚未核实 | 继续查原始来源、历史版本或更直接的材料 |
| 用户可知的目标、资源、经营数据或约束 | 说明该信息怎样影响判断，用问答请求补齐 |
| 用户也未必知道的外部公司内部事实 | 保留未知，寻找有限代理证据或给出条件性判断 |
| 只有试验或未来行为能回答 | 设计验证方法；询问能否提供已有结果，不能要求用户凭空给答案 |

问答按决策影响排序，每轮通常问 1–3 个最重要的问题。每个问题包含已知背景、缺口、为什么要问，以及容易回答的口径或选项。允许“不知道”“暂不方便提供”和区间回答；接受不精确回答时降低对应结论的精度。公开资料已回答的问题不再重复问。

等待回答时继续独立研究。只有依赖缺失信息的结论暂缓；不要因一项缺口停止整个任务，也不要把暂定假设写成确认事实。可使用可用的异步问答工具；没有工具时用简洁编号问题。用户没有回答不代表同意某个选项。

收到回答后更新证据台账和受影响的判断，指出哪些假设得到支持、哪些需要修改，再问下一轮。标记“用户提供”、时间、口径及是否有记录佐证；用户估计不能升级为独立核验事实。用户的纠正优先更新其自身信息，若与其他材料冲突则保留并解释差异。

## 4. 从材料形成机制判断

重建关键阶段的“当时约束 → 可选方案 → 实际动作 → 结果证据 → 下一阶段变化”。首批客户、第一次收入、人工交付、产品化与扩张往往比融资新闻更能解释业务。阶段可以并行，不强行编排成整齐的成功故事。

对标围绕具体机制选择公司，说明入选原因和不可比之处。关键对标应有公司档案、早期路径、结果证据、依赖条件与迁移限制；资料允许时补充失败、停滞或不同路径的反例。名单、融资金额和功能表不能代替深入对照。

将事实、综合解释、实践建议就近区分。关键数字保留对象、单位、分母、时间窗和来源。特别区分注册与付款、交易额与公司收入、融资与客户收入、合作关系与可支配资源、团队履历与实际责任。

“增长飞轮”中的每条反馈都应解释如何改善下一轮价值或成本，并标记哪些箭头尚未验证。融资动机、因果效果和护城河需要直接依据或明确推断标签，不能因为来源网页写得肯定就直接继承。

## 5. 交付研究与可执行的下一步

报告先给核心判断和依据，再展开公司现状、具体业务、路径和机制。对于需要作出路线选择的任务，比较真实备选方案的客户、产品、资源、经济性、前提和失效条件，明确推荐、条件性推荐或暂缓的理由。

如果用户要求对已有建议作复盘，逐项给出“采用、带条件采用、暂缓或否定”，说明证据和条件；没有原建议时不虚构一个复盘对象。

行动计划从主要未知和约束推导。按实际业务周期设置近期调查、试验与复盘节点；适合时采用 30/60/90 天。每项写清目标、最小动作、负责人角色或待确认责任、资源、观察指标、继续或停止条件。此处是建议，不替用户承诺人员投入，也不自动联系第三方、发布或执行商业动作。

交付前逐项检查参考文件中的覆盖表。适用的重要模块缺失时先补研究；资料不足时列明已查范围、影响、待答问题或验证方式，交付带缺口的阶段性结论。**不能把“写了未知”本身当作已经达到参考网页的实质深度。** 用户明确缩小范围时按其范围交付并说明边界；没有缩小范围时，不自行降为公司简介。

最终结果应让用户看清：公司靠什么运行，哪些机制已经证明，最关键的约束是什么，哪些经验能迁移，什么证据会改变结论，以及下一步由谁确认什么。
