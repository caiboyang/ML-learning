# 公司调研执行规范

这份 skill 供 Agent 研究公司如何从起点走到可重复经营，并为当前业务选择可借鉴的路线。核心顺序是：**证明状态 → 现有业务与可调用资产 → 冷启动资产对标 → 行为路径与机制 → 分阶段迁移 → 当前主路线 → 验证计划与数据合同**。换公司时替换证据、资产和动作，保留这条推导链；不能将它改成一份平铺的通用商业分析清单。

开始完整调研时读取 [研究深度与问答合同](references/research-contract.md) 和 [结果组织与呈现规范](references/result-presentation.md)。前者定义分析覆盖与信息补齐，后者定义信息架构、页面分区、图表选择、排版与交互。研究方案同时说明查什么和怎样展示，不能等正文写完才补排版。核心流程由本 skill 与上述两个参考文件定义；仓库中的公司调研方法报告提供更长的解释、教学案例和模板。

## 1. 确定此次研究要支持的判断

先利用已有对话确定研究对象、具体业务、目的、时间范围和交付格式。区分两种常见任务：

- **理解目标公司**：解释它如何启动、创造价值、成交与增长。用户未必知道它的内部数据，不能把这些问题反复转交用户。
- **为用户自己的业务借鉴经验**：既研究目标公司，也调查用户业务的阶段、资源、客户、已有证据和执行限制。迁移结论依赖这两侧的资料。

用户没明确目的时，可以暂按“理解业务机制与可借鉴经验”推进，并说明假设；若公司身份、业务边界或决策目的存在实质歧义，尽早提出少量问题，同时推进无依赖的资料核对。不要先抛一份长问卷，要求用户完成研究。

## 2. 先判断证明状态，再识别起步资产

读取用户指定材料的正文和关键子页，核对官网、产品、历史公告、创始人叙述、客户材料及已授权数据。记录事件与核对日期，区分现状和历史。先按业务类型选证明命题，再做“已证明／有信号／未证明／反证／不适用”表。付费服务可检查交付、付款、结果、持续使用、再次付款、供给复制；消费社交应检查激活、同批留存、回访频率、内容沉淀、创作者留存与变现条件。企业软件和双边平台另按续约、部署或两侧供需定义命题，见研究合同。不适用必须写原因，不能与缺证据混用。自报数据保留来源性质；一次成功不能证明稳定经营。

为团队单列每人一行的角色、相关背景、实际职责、投入与证据；公开未披露的责任写未知，拟议负责人写待确认。统计聚合站只作检索线索；数量主张必须核对原始披露或有公开定义、样本和方法的原始测量。无法追溯底层材料和日期的数字不作为证据，多站转载不算独立佐证。

盘点当前产品、渠道、资源和责任，分别标记已交付、活动、原型、计划；分清产品收入、获客入口与交付工具。对每项资产追问：谁控制、承诺投入多少、降低哪项冷启动困难、实际带来什么结果、用完后如何补充。把专家履历、已有受众、客户关系、预算入口、技术窗口等连到真实业务动作，不能只列资源清单。

产品清单按支持当前判断的验证强度排序，保留已交付、活动验证、原型、计划、持续供给等状态及其时期与来源；状态标签不自动代表证据强弱。盘点后给产品组合判断：哪项承担主要收费，哪项是入口或工具，哪项是下一验证方向，证据不足则暂不指定旗舰。渠道逐项说明主渠道、转化页、放大器、品牌说明、信用背书或缺口等角色，以及归属、线索流向和来源记录；再提出本阶段的渠道取舍，不默认要求所有公司只有一个主渠道。

建立“对标公司当时借用的资产 → 如何转为首批客户或供给 → 目标业务实际拥有的对应资产 → 缺口”的对照。先据起点和阶段匹配挑重点案例，再核对客户、机制与经济性；保留资产不同的对照，解释为什么暂不能照做。

客户选择、市场估计、单位经济和因果检验是按缺口调用的补充工具。竞品或产品机会任务可以从“谁因什么触发，替换什么旧方案，为何付费”深挖；默认创业路径研究仍先判证明状态与起步资产。八个调查角度是覆盖检查，不替代核心顺序。

## 3. 把未知分流到取证或问答

每个未知先判断属于哪一类：

| 未知类型 | Agent 的下一步 |
| --- | --- |
| 公开可查，但尚未核实 | 继续查原始来源、历史版本或更直接的材料 |
| 用户可知的目标、资源、经营数据或约束 | 说明该信息怎样影响判断，用问答请求补齐 |
| 用户也未必知道的外部公司内部事实 | 保留未知，寻找有限代理证据或给出条件性判断 |
| 只有试验或未来行为能回答 | 设计验证方法；询问能否提供已有结果，不能要求用户凭空给答案 |

问答按决策影响排序，每轮通常问 1–3 个最重要的问题。每个问题包含已知背景、缺口、为什么要问，以及容易回答的口径或选项。允许“不知道”“暂不方便提供”和区间回答；接受不精确回答时降低对应结论的精度。公开资料已回答的问题不再重复问。

等待回答时继续独立研究。只有依赖缺失信息的结论暂缓；不要因一项缺口停止整个任务，也不要把暂定假设写成确认事实。可使用可用的异步问答工具；没有工具时用简洁编号问题。用户没有回答不代表同意某个选项。

收到回答后更新证据台账和受影响的判断，指出哪些假设得到支持、哪些需要修改，再问下一轮。标记“用户提供”、时间、口径及是否有记录佐证；用户估计不能升级为独立核验事实。用户的纠正优先更新其自身信息，若与其他材料冲突则保留并解释差异。

## 4. 拆解对标的动作，再判断迁移顺序

每家进入横向矩阵的公司都要有同结构拆解：一句机制判断、起点与切入点、关键动作及结果、增长机制、可借鉴与不可照搬的做法、风险和直接来源；不能以矩阵一行代替分析。按**实际行为顺序**拆路径，每步包含阶段标签、时期、动作事实、结果证据、机制判断及限制。洞察、团队、切入点、人工验证、收入证明、产品化、扩张是可选阶段，不强迫所有公司走相同六步，也不把融资新闻当作业务路径。

重点案例必须解释四个问题：互补资产怎样共同降低启动难度；最初如何验证交易和交付（实际存在人工服务时拆出具体流程与产品化触发）；当时做了哪些取舍（已证实的不做与研究者总结的反模式分开）；增长回路怎样形成、哪些边尚待验证。使用 [研究合同](references/research-contract.md) 中的案例模板。

学顺序，不照抄终局功能。将每项可借鉴动作归为“现在复制／以后复制／谨慎借鉴／暂不复制”，逐项写对应资产、缺失条件和进入下一阶段的证据。机制相似不能替代资源可用性；成功样本之外适当加入失败或不同路径的对照。

研究爆发后放缓、衰退或转型时，分别检验环境变化、竞争复制、产品自身回路中断；写各自支持证据、反证、不能排除的解释和区分所需数据，不凭时间先后定因果。

事实、解释、建议就近区分；保留对象、单位、分母、时期和来源。注册不等于付款，交易额不等于公司收入，融资不等于客户收入，接触资源不等于可支配资源。每条增长反馈都要解释如何改善下一轮价值或成本；融资动机、因果与护城河不能仅凭材料语气成立。

## 5. 将分析组织成可阅读和比较的结果

先确定读者的三条路径：快速判断、理解与比较、核实与执行。默认按“阶段与决策 → 业务与起步资产 → 对标路径与机制 → 迁移与路线 → 验证与数据合同 → 证据与问答”六部分组织，按任务合并或调整；调查角度不必直接充当页面目录。

外部公司研究改用“阶段与判断 → 业务与起步资产 → 对标路径与机制 → 关键决策复盘 → 借鉴顺序 → 下一步调查与数据缺口 → 证据与问答”。这会改变研究内容，不能只替换栏目名。

首屏呈现研究对象与时期、主判断、关键证据和主要未知。每个分析章节先给一句论点，再按“图表或结构化数据 → 机制解释 → 限制与来源”展开，节末落到结论与决策含义；来源索引等辅助章节无需重复结论。主页面负责摘要和导航，重点公司、横向比较或建议复盘过长时再拆详情，并保留返回与证据跳转；详情页结尾连回验证与数据合同，外部公司研究则连回下一步调查。

根据阅读任务选择形式：产品与渠道用同字段卡片或表格，公司与路线用矩阵，历史用时间线，价值交付用流程图，反馈用回路图，行动用里程碑表。关键指标显示单位、分母、时期、口径与来源；主观评分无明确尺度时不用评分图。正文解释机制和限制，不能把所有内容切成同样的卡片。

按呈现规范设置视觉层级、阅读宽度、间距、颜色语义、筛选范围、窄屏和静态输出。完整调研默认使用模板交付可双击离线打开的单文件 HTML；Markdown 是按需提供的文字版。用户明确指定其他格式时遵从，不自动部署或发布。结论、证据、假设、问题与行动互相连接；用户回答后，同步更新摘要、图表、路线与行动。完整调研开始时读取 [数据与模板约定](references/dashboard-data.md)，复制 [页面起点](assets/research-dashboard/index.html) 及同目录资源；替换虚构数据，通过 schema、引用和内容覆盖检查，用 [导出脚本](scripts/export-report.py) 打包，再验证离线阅读和专题跳转。模板是展示起点，不是已完成的公司研究。

## 6. 收敛决策，交付验证计划

有路线选择任务时，用资产、阶段、证据与机会成本比较真实备选项，推荐一个当前主路线。早期验证明确一类优先客户、一个主要产品承诺和一个结果标准，其余能力放到后续阶段；不把单一产品要求套到成熟多业务公司。证据不足以选定路线时，给出暂定路线和决定分歧的最小问答或实验，不制造确定性。纯外部公司研究以可借鉴顺序与下一步调查交付，不虚构运营授权。

纯外部公司研究单列关键决策复盘：当时约束和可知信息、真实备选及其来源、实际选择、后续结果、机会成本、研究者解释和反证。研究者构造的备选要明示，不能替公司补写动机或内部讨论。选择后的结果不等于选择导致的结果。

已有建议按“立即采用／带条件采用／明确删除”复盘；尚不能判断的另列待确认。正式预算与排期前逐项检查 **可控、可证、可信、可重复**：交付承诺可控、结果可观察、证据真实、资源与容量支持多个完整周期。未通过的项先补证或进入有边界的试验，不包装成已验证方案。具体判据见研究合同。

形成会议摘要，每条写“决定什么—依据—成立条件—谁确认—何时复盘”，并按语义标“必须确认／信任底线／产品边界／明确删除”。不用凑固定条数；确认类型与建议采纳状态分开。

为主路线制作验证计划：默认用 90 天的确定范围、获客验证、交付观察、复盘再售四个阶段，周期依业务调整。每项写最小动作、责任角色或待确认责任、资源、观察指标及继续／停止标准。同时建立数据合同：独立对象标识、实付与退款、分期留存、结果标准、再次付款、交付工时、渠道来源、窗口活跃；按业务替换字段，明确口径、记录来源、负责人和更新周期。证据台账管论断，数据合同管下一轮实际记录，二者不能互相替代。

收到用户回答或新数据后，标注判断上调、下调或维持及原因，同步改阶段、资产匹配、主路线、摘要图表与动作。允许推翻先前推荐；不能只追加问答而保留旧结论。

交付前逐项填写研究合同末尾的内容覆盖清单，记录实际章节或记录 ID、依据与缺口；另查呈现规范的交互质量。团队、每家对标拆解、数据核验、关键决策复盘不能因浏览器或 schema 测试通过而免检。适用关键项缺失时先补研究；拿不到的数据说明已查范围、影响及验证方式。写了“未知”本身不算完成实质分析。用户明确缩小范围时遵从其范围；不自行降为公司简介，也不自动执行商业动作。
