# 公司调研

供 Agent 执行的主链：**证明状态 → 业务与可调用资产 → 起点匹配与行为路径 → 机制及反证 → 分阶段迁移 → 当前选择 → 验证与数据合同**。换公司时替换具体证据、资产和动作，不能只替换公司名称。

## 开始

从已有对话确认对象、业务、时期、用途和输出格式。区分“理解外部公司”和“为用户自己的业务做决策”；前者不虚构经营授权，后者需要用户侧的资源与约束。用户代表该业务且要决定下一步时按自有业务决策；只理解别家机制时按外部研究。内部访问权限只是取证条件，不自动决定任务类型或授予经营权限。仍不明确时问“这次是帮这家公司做决定，还是研究它可以借鉴什么？”，同时继续共同取证。自有业务先查已有方案、建议或团队计划；对话未提供时再问，口头计划也可复盘。

完整调研先读 [研究合同](references/research-contract.md) 与 [呈现规范](references/result-presentation.md)，同时设计研究问题和结果议程。本文只编排执行；详细规则分别由这两个文件维护。

## 执行与检查

| 步骤 | 动作 | 必须得到的产物与检查位置 |
| --- | --- | --- |
| 1. 定证明状态 | 核对用户材料、产品、原始披露与已授权内部记录，先复算可得数据，再按业务定义命题 | 状态、依据、缺口、下一证据；[内部取证](references/research-contract.md#已授权内部记录的取证与复算)、[证明命题](references/research-contract.md#证明命题随业务改变) |
| 2. 找实际起点 | 盘产品、渠道、团队、资源控制与投入，连到首批客户和供给 | 产品组合、渠道角色、团队分工和资产匹配；[覆盖要求](references/research-contract.md#完整研究的覆盖与验收) |
| 3. 拆行为和机制 | 按发生顺序核对动作与结果，比较相近起点及不同路径 | 自身路径、逐家对标、按借鉴任务选择的四模块重点案例与反馈边；[案例合同](references/research-contract.md#重点公司专题的最低结构) |
| 4. 复盘关键选择 | 区分当时信息、实际选择、研究者备选、后续观察和反证 | 历史决策、竞争解释；[决策与诊断](references/research-contract.md#关键决策复盘与衰退诊断) |
| 5. 决定如何借鉴 | 对照用户资产，区分当前、以后、谨慎和暂不复制 | 借鉴顺序；有决策任务时补主路线、建议复盘和会议摘要；[决策门槛](references/research-contract.md#迁移决策门槛与会议摘要) |
| 6. 补关键未知 | 公开可查的继续查；已授权内部记录可得的自己算；只有用户知道的少量提问；其余给条件性结论与验证 | [问答与更新](references/research-contract.md#怎样提问才有用)、[数据合同](references/research-contract.md#下一轮经营数据合同)；收到回答后更新受影响判断 |
| 7. 组织与验收 | 主页面完整呈现产物，按分析深度增加子页；逐项核对内容和展示 | [主页面与专题分工](references/result-presentation.md#主页面与专题分工)、[内容覆盖清单](references/research-contract.md#内容覆盖清单交付时逐项填写) |

## 交付

交付格式、实现、导出与测试以 [数据与模板约定](references/dashboard-data.md) 为准。[自有业务数据](assets/research-dashboard/research.json) 与 [外部研究数据](assets/research-dashboard/external-research.json) 都是明确标注的虚构测试夹具，只演示字段和阅读流程；执行研究时重新取证，不将示例内容当成事实或指定的研究对象。

交付前填写并校验 [coverage 覆盖数据](references/dashboard-data.md#覆盖清单数据)，在页面逐项展示完成程度与缺口；再沿主判断追到动作、口径、直接证据和反证。关键资料取不到时说明已查范围、判断影响和下一步；通过页面或结构测试不等于研究完成。用户缩小范围时遵从其范围，保留对应证据边界。
