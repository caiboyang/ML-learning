03
复杂度推演：累积开销为何能从 O(T²) 降至 O(T)？
核心症结在于“历史信息在每一轮被全量重传”。若第 1 轮的内容在后续轮次中被无休止地重复发送，同一段历史就会被累计计算 T 次，诱发输入的二次方膨胀。

假设：固定规则 1,000 token；每轮新增历史 200 token；固定状态 800 token；新观察 200 token。不含输出、缓存折扣、工具调用或延迟，不能当作实际账单。

 
每轮输入越来越长
Σ (1,000 + 200t)
 = 1,000T + 100T(T+1)
随着 T 增大，T² 那一项占主导。这是全历史重复输入的累计复杂度。
每轮输入长度固定
Σ (1,000 + 800 + 200)
 = 2,000T
每轮都只有规则、状态和最新观察，总量随步数线性增加。

  
“单步 O(1) 输入”存在严格前提：状态字典与单步观测的体积不能随执行步数无界膨胀。 固定了 5 个 JSON 字段名，绝不等于其内存体量恒定：例如 tested_hypotheses（已测试假设）列表可能随探索持续追加。若系统必须追踪的实体规模 N 随执行步数 T 增长，单步输入依然会线性膨胀。论文 §3.3 的复杂度推导仅在 |P|、|Σ|、|O| 均严格有界时成立；事实上，滑动窗口或定额预算摘要机制下的累积输入规模同样为 O(T)。推导 ↗

深度审视：原文中哪些论断需要保留学术质疑？
① §5.2 宣称“在所有 Horizon 尺度下均匹配或超越基线”，该结论仅适用于表 1 的仓储受控测试，无法推广至全部场景：表 6 软件仓库 T=25 步时，SKILL.state 均值为 0.88，低于 Stateful 的 0.94。图表如实保留了这一均值波动。
② 表 4 题注笼统称 Prompt 显著缩小，但在 Retail 场景中 SKILL.state 的单步 Prompt 字符数反而是四组中最大的（3,325 字符）。总 Token 下降主要得益于完成步数减少，不能将总开销缩减简单等同于单步输入微型化。
③ CTF 涵盖 100 道赛题，表中却出现了 54.2% 等非整数百分比，表明涉及多次评测的均值聚合，但原文未能独立推导出分母与评测轮次，本篇严格按原表忠实呈现。
④ 设定 temperature=0 与 top-p=1 并不天然保证远端服务推理完全确定；合成任务的统计显著性结论不能无条件覆盖至所有公共基准测试。
⑤ 基线方案的总结周期、摘要预算上限与 LLMLingua 压缩配置直接决定对比结论；表中累计 Token 缺乏输入、输出及中间调用的拆分明细，复现与商业账单折算前需补充口径。

 
当前证据能够支持哪些结论？上述实验有力证实了：在特定受控任务与状态空间闭合的环境下，显式状态维护能显著抑制冗余开销；但绝不能据此轻率宣称所有文本摘要方案均已落后、编码智能体应全面摒弃历史上下文，或实际商业账单能够无条件实现同等倍数的缩减。

06
核心前提审视：状态是否构成了完备的“充分统计量”？
论文将状态 Σ 视作未来决策的充分统计量（Sufficient Statistic）。通俗而言：即假定仅凭当前状态字典，便绝不遗漏未来任何决策所需的历史信息。

 
以两段不同历史路径，检验同一份状态
历史 A：货物到库，直接上架至 42 号架历史 B：货物先到 12 号架，后搬移至 42 号架
→
{ "item_12": "shelf_42" }
发货决策仅需当前物理坐标：此场景下状态确实构成充分统计量。
将提问反转：“这件货物此前是由谁操作移库的？” 两种截然不同的流转历史被投影为了完全相同的静态状态，然而溯源问题的答案却彻底丢失。被剪除的历史瞬间成为了任务本身的关键考量。失效的根源并非模型能力不足，而是所需信息在状态投影阶段已被不可逆地剔除。

 
边界 1 / 动态 Schema 困境
难以预先穷尽所有字段
在开放式探索或复杂未知代码库逆向中，关键状态维度往往是动态演进的。预先固化的静态 Schema 极易因缺乏扩展性而无法承载新发现的语义关联。
边界 2 / 迟滞相关性
初期看似无关，后期方显关键
早期日志中某个不起眼的异常报错，在数十轮后可能被证实为故障根因。若未能在初始阶段写入状态，且系统缺乏历史检索回溯通道，该信息将永久湮灭。
边界 3 / 轨迹即任务目标
必须阐明“为何做出该决策”
合规审计、因果归因与复盘依赖完整的执行过程证据链。最终的状态快照无法替代对操作轨迹、中间观测及推理来源的完整追溯。

 
上述三项边界源于论文 §7 自身的严谨界定。此外，多 Agent 并发写入机制在本文单 Agent 实验中未经验证；共享状态需要引入严格的版本管理与分布式冲突裁决。Limitations ↗

反例压力测试：遭遇“迟滞相关性”信息如何应对？
在第 2 步观测中提及“实验仅在单 Agent 上完成”，用户在第 20 步才提问多 Agent 扩展性。若该细节在第 2 步未被写入状态字典且未沉淀至证据库，纯状态机模式将彻底丧失回答依据。证据库提供了按需检索的可能性，但仍需严密验证检索算法的召回准确率 —— 物理存储于磁盘并不等价于模型能准确利用。

核心工程判据：针对状态空间明确、操作契约稳定的封闭式工作流，纯状态驱动循环具备极高的执行能效。而对于开放式探索与深度研发任务，必须为“当前重要性未知、后续可能关键”的非结构化信息预留可寻址、可回溯的检索通道。
