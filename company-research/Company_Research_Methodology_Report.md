# 公司调研方法报告

这份报告供 Agent 在研究不同公司时复用，解释从哪个角度切入、怎样形成判断，以及如何把结果组织成可阅读、可追证的页面。读者只需明确研究对象和用途；公司事实、研究时期与用户约束在每次任务中重新取得。本文不绑定某家公司，也不依赖另一个网站才能执行。

核心方法是：**证明状态 → 业务与可调用资产 → 起点匹配与行为路径 → 机制及反证 → 分阶段迁移 → 当前选择 → 验证与数据合同**。八个调查角度为这条主线补证；页面结构让读者看见完整推理和证据边界。

执行入口是 [公司研究 Skill](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/SKILL.md)。详细验收分别由研究合同、呈现规范和数据约定维护；本文解释为什么这样研究以及怎样应用，不另复制一套字段合同。方法报告只维护 Markdown。

| 阅读顺序 | 要回答的问题 | 得到的产物 |
| --- | --- | --- |
| 一、确定任务 | 研究帮助谁作出什么判断？ | 对象、业务、时期、用途、范围 |
| 二、证明状态 | 已经证明什么，数字不能证明什么？ | 命题、证据、缺口、下一证据 |
| 三、业务与资产 | 价值怎样交付，起步靠什么？ | 产品、客户、渠道、资源与团队地图 |
| 四、行为与选择 | 公司实际做了什么，当时为什么可能这样选？ | 自身路径、关键决策及机会成本 |
| 五、机制与反证 | 哪些动作可能解释结果，还有哪些解释？ | 反馈边、竞争解释与证伪条件 |
| 六、对标与迁移 | 哪些动作适合当前条件，顺序是什么？ | 逐家拆解、横向矩阵、迁移与路线 |
| 七、调查工具 | 当前缺口需要调查哪个业务环节？ | 八个角度对应的证据与分析 |
| 八、问答与更新 | 哪些未知应问用户，回答如何改变判断？ | 少量高影响问题、判断变化与下一行动 |
| 九、组织与展示 | 如何让读者理解、比较、核实和使用结果？ | 完整主页面、深入专题、图表与交互 |
| 十、执行与交付 | 什么顺序推进，什么程度算完成？ | 研究闭环和交付检查 |

## 一、先问这次研究要帮助谁做什么判断

“这家公司为什么成功”容易引导研究者从结局倒推故事。更可研究的问题是：“它怎样找到第一批客户，怎样交付价值，哪些环节已经重复发生，哪些仍依赖特殊条件？”如果用途是借鉴，还要问：“用户实际控制什么资源，下一步需要验证哪一个前提？”

先确认具体业务和时期。同一家公司在不同阶段可能有不同产品、客户、收入和渠道。早期试验与成熟业务分别分析，不能把今天的品牌、团队或分发能力倒填进起步阶段。

| 任务类型 | 应形成的判断 | 下一步的责任边界 |
| --- | --- | --- |
| 理解外部公司 | 业务机制、发展路径、关键选择、证据边界 | 研究者继续调查；不替目标公司安排经营排期 |
| 为用户业务借鉴 | 当前资产与约束、可行路线、取舍和采用条件 | 与用户确认资源、责任及验证窗口 |
| 比较多家公司 | 同一问题下的起点、动作、结果与差异 | 解释可比范围，不用统一评分掩盖业务差别 |

从已有对话提取这些信息；用户已经明确的内容不重复询问。先结合用户的角色和要作出的决定判断任务类型；可读内部数据只是取证条件，不能代替用途与经营授权。仍不明确时问这次是帮助该公司作决定，还是理解可借鉴的经验，并继续两者共同需要的取证。自有业务还要先查已有方案、顾问建议或团队计划，未提供时再询问。

## 二、证明状态是第一张表：把不同层的证据拆开

从“公司拥有什么”转到“业务已经证明了什么”，才能找到研究切口。有产品只能证明某种能力已被做出来；有人使用、愿意付款、得到结果、再次使用，以及其他人能重复交付，是需要分别核对的命题。

例如，**以下只是数字口径示意**：一批 100 名报名者中有 20 人付款，其中 12 人达到事先约定的结果。如果三者属于同一批且观察窗口一致，可以计算付款占报名者的 20%，以及达标占付款者的 60%。这些数字仍不能证明复购、利润或另一批客户会得到相同结果。若人数来自不同批次，连这两个比率也不能直接相除。

| 业务类型 | 优先检查的命题 | 容易误用的替代指标 |
| --- | --- | --- |
| 付费服务 | 交付、付款、成果、持续使用、复购、供给复制 | 出席代替成果，意向代替付款 |
| 企业软件 | 部署、实际使用、客户结果、续约、净扩张、实施成本 | 签约代替使用，席位代替效果 |
| 免费产品或社区 | 激活、同批留存、回访频率、持续供给、变现条件 | 下载代替活跃，总活跃代替同批留存 |
| 双边平台 | 两侧激活、匹配、履约、重复交易、两侧留存、单位经济 | 供给名单代替有效供给，交易额代替收入 |

每个命题保留五列：命题、状态、支持证据、尚缺什么、下一证据。状态区分已证明、有信号、未证明、反证和不适用；不适用必须说明业务原因。尚未拿到数据不能成为排除重要命题的理由。

数字旁边写清对象、事件、分子、分母、时间窗和来源身份。未知、零、未到观察期不能混写。用户自报应保留自报标签；公开披露也不自动等于独立核验。已有授权内部系统时，先盘点字段并自己重建同批数据，记录去重键、分母、窗口、读取范围和计算方法。能算出的不转成问题问用户；报告只给必要汇总与脱敏证据位置，不导出个人明细。证明表产生的关键缺口，决定下一章优先调查什么。

## 三、先画业务地图，再判断资源是否真的可调用

业务地图要能走通一次完整价值交换：谁遇到问题，通过什么渠道到达，由谁用什么产品或服务完成交付，谁验收和付款，收入留下多少，又需要哪些持续投入。使用者、受益者、决策者与付款者可能不同；产品宣传页往往只讲其中一段。

| 盘点对象 | 需要写到的具体内容 | 如何接回判断 |
| --- | --- | --- |
| 产品与交付 | 对象、承诺、关键动作、结果标准、人工环节、时期 | 产品能力是否变成可观察结果 |
| 渠道 | 入口、控制者、客户批次、实际转化、合作归属 | 首批客户从哪里来，能否重复触达 |
| 资产 | 专业知识、技术、受众、关系、供应链、资金、控制权与承诺 | 哪项资源解决哪个经营瓶颈 |
| 团队 | 每人角色、背景、实际责任、投入与来源 | 交付责任是否有人承接，容量有多大 |

资源必须连接到动作。认识专家不等于拥有专家固定投入；合作方的客户不等于自己控制的分发；创始人的背景只有改变需求理解、产品、成交或交付时，才构成这里要解释的起点优势。

对每项关键资产追问：谁控制、投入多久、容量多大、对价是什么、如果撤回有什么替代。外部研究拿不到承诺信息时标为未知，不能写成没有投入。起步优势也不等于持续优势：人脉可能带来首单，下一步仍需调查陌生客户是否会购买。

这张地图为对标选择提供依据。先知道目标业务拥有什么、缺什么，再寻找在相近起点解决过相似问题的公司，避免直接模仿成熟公司的最终产品组合。

## 四、重建行为路径，同时保留当时的选择空间

路径不是里程碑新闻列表。每一步要解释“在什么约束下，谁调用什么资源，采取什么动作，观察到什么结果，又留下什么未证明的环节”。一轮人工交付尤其要拆清获客、理解需求、收费、服务、验收与反馈，才能讨论何时适合产品化。

用带时期的动作表记录事实顺序；并行发生的工作保留并行，不为了套用阶段模板强行排成线性成功故事。资料没有证明的阶段不补写，未找到失败尝试也不能推断公司主动克制。

关键转折另做决策复盘。它回答的不是“今天看怎么最好”，而是“当时有哪些信息和约束，这项选择交换了什么”。

| 复盘层次 | 需要保存的内容 | 防止的误判 |
| --- | --- | --- |
| 当时背景 | 日期、约束、当时已知数据 | 用后来结果替当时决策背书 |
| 选择空间 | 实际选择；已披露备选与研究者构造备选分别标注 | 把研究者建议写成管理层讨论 |
| 行为与结果 | 实施动作、后续观察、时间差与口径 | 把时间先后直接写成因果 |
| 解释与代价 | 可能机制、机会成本、其他解释、未知 | 只讲收益或假定管理层动机 |
| 反证 | 什么资料会推翻或降低解释 | 只收集支持原结论的材料 |

重点公司专题可进一步拆成互补起点资产、首次交易与交付验证、取舍与反模式、回路与迁移四部分。模块的目的在于解释动作之间的关系，步骤数应随证据增减。详细合同见 [重点公司专题](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/research-contract.md#重点公司专题的最低结构)。

## 五、机制必须能解释回流，也必须允许被推翻

增长机制至少需要一条可解释的反馈关系：上一轮业务留下了什么，它怎样改善下一轮的供给、分发、结果或成本。只有“获客 → 使用 → 收费”的箭头更接近流程；要称为反馈，还需解释产出如何重新作用于下一轮输入。

| 每条反馈边要回答什么 | 记录方式 |
| --- | --- |
| 什么产出被留下？ | 客户成果、转介绍、可复用流程、有效供给等具体对象 |
| 谁通过什么动作使用它？ | 明确参与者与回流步骤，不能只写“数据积累” |
| 哪项结果可能改善？ | 相同口径的成本、转化、质量、周期或留存 |
| 已观察到什么？ | 对应证据、样本与窗口，区分观察与假设 |
| 哪个条件失效会切断回流？ | 容量、质量、激励、匹配、信任或外部依赖 |

对增长放缓、衰退或转型，同时检验环境与需求变化、竞争或分发替代、产品自身反馈中断。为每种解释写机制、时序、支持证据、反证，以及最能区分它们的下一份资料。多种原因可以并存；资料不够时给有条件的解释排序。

证据台账以“主张”组织，而不只是收藏链接。每条记录含来源身份、日期、具体位置、支持范围与局限；事实、综合解释、行动建议分别标注。转引数字要追到底层披露或有方法说明的原始测量，同一来源的多次转载不能当多份独立证据。

沿主判断做一次反向审查：从结论回到机制、实际动作、数字口径、原始材料，再问是否存在同样符合证据的另一种解释。找不到这些连接时，应降低判断强度或补证，而不是用更肯定的语言填补。

## 六、先匹配起点，再决定学哪些动作、按什么顺序学

选择对标时先写它要回答哪项问题。可以选起点相似而路径不同的公司，也可以选动作相似但资产不同的公司，用差异检验条件；失败或受阻样本有助于暴露机制的边界。公司知名度不是入选理由。涉及借鉴路径时至少选一家重点案例，优先接近候选路线的起点资产与阶段，解释选它及未选其他对象的原因；再用研究结果修正路线。材料不足时标关键缺口与已查范围，不能静默跳过或补造步骤。

每家进入横向矩阵的公司，都应有可继续阅读的完整拆解：一句机制判断、起点与切入点、带时期的关键动作与结果、反馈关系、可迁移与不可迁移、风险与直接来源。不能用若干简介或矩阵一行代替逐家研究。

矩阵统一比较阶段、起点资产、首批用户、最初产品、收入证明、扩张依赖、目标业务的资产差距与当前可学动作。相似度没有明确定义时用文字解释，不制造精确分数。比较收入或使用规模前，先确认时期、业务边界与指标口径可比。

| 迁移分类 | 需要回答的问题 | 应交付什么 |
| --- | --- | --- |
| 现在复制 | 当前阶段与关键资产是否匹配？ | 最小动作、观察指标、承载上限 |
| 以后复制 | 哪个必要前提还没具备？ | 前置验证与重新评估条件 |
| 谨慎借鉴 | 哪部分机制成立，哪部分依赖不同？ | 保留与调整项、失败界限 |
| 暂不复制 | 当前机会成本为何过高？ | 暂缓理由及可能重启的条件 |

如果任务包含用户业务决策，在真实可行的备选间推荐当前主路线，说明放弃什么以及为什么。早期验证可收敛到一类优先客户、一个主要承诺、一个结果标准；成熟多业务公司不能被机械压成单一产品。证据不足时给暂定路线，并定义能决定分歧的最小验证。第二阶段是在主路线达标后升级；备选是在特定条件触发时切换，写明时间点、未达标条件与替代动作，不把它混入暂缓。

路线进入预算或排期前检查可控、可证、可信、可重复四道门槛。未满足重复性时可以开展有限试验，但不能把试验写成已经稳定交付。把路线转成阶段动作、责任、资源、观察窗口与继续／停止条件，并约定下一轮需要记录的数据。

先盘点已授权系统中已有字段、能复算的指标和口径缺口，避免让用户重复填报。数据合同只新增缺失或需修正的采集要求，已有字段保留位置与更新安排；按路线选择客户或订单标识、实付与退款、同批留存、成果、再次付款、交付工时、渠道归属和有效活跃等字段，写清记录位置、角色与频率。会议摘要另列决定、依据、条件、确认角色和复盘时间。具体门槛与字段由 [研究合同](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/research-contract.md#迁移决策门槛与会议摘要) 维护。

## 七、按缺口调用工具，而不是把公司拆成八篇互不相连的文章

下面八个角度用于补足前面推理中的缺口。每次选用时，先说明它要帮助区分哪两种解释：付费弱可能来自客户不匹配，也可能来自采购阻力；收入增长而现金紧张可能来自交付成本，也可能来自回款节奏。分析产物应接回主判断，而不是停在独立资料汇总。

### 7.1 客户与需求

首先定义细分客户。角色、能力、组织规模、触发事件和预算来源，往往比年龄或“高端用户”等标签更能解释购买。理想客户画像，即 ICP，应描述最适合当前产品的一类客户，并说明哪些人暂不适合。

区分使用者、受益者、决策者和付款者。在企业业务中，员工可能获得效率收益，部门负责人决定采用，采购与安全团队审批，预算则由另一个部门承担。公司需要同时解决使用价值和购买流程问题。

调查重点包括问题频率、严重程度、现有解决成本、紧迫性、可触达性和预算。证据优先来自真实工作记录、现有采购、替代工具、客户访谈和失败交易。问“最后一次怎么处理”，比只问“你需要什么功能”更容易发现真实限制。

市场规模要从符合条件且可触达的客户开始估算。可以用“符合条件的组织数 × 合理年度支出”构造需求情景，再检查付费比例、销售能力和交付容量。人口数量、行业总支出和网站访问量，不能直接当成可获得收入。

该角度应产出：一个明确客户群、一个购买触发、现有替代方案及其不足，以及需求证据的强弱。对于市场估计，保留区间、假设和口径，避免用单个精确数字掩盖未知。

### 7.2 产品与价值

产品分析应解释客户状态如何变化。把主张写成“某个客户在某种条件下，通过某项关键动作获得某种改善”，然后检查每个环节是否存在证据。

研究真实使用路径：首次获得价值需要多久，需要输入哪些资料，谁配置产品，在哪一步容易失败，失败后谁补救。帮助文档、演示、实际使用观察、工单和实施记录，往往能补充宣传页省略的工作。

建立结果标准。例如，节省时间需要包含复核与返工；提高准确率需要定义任务、样本和错误代价；提高销售额需要考虑价格、渠道和季节变化。客户满意可以支持体验判断，不能独立证明财务收益或因果效果。

同时寻找反例：哪类客户没有获得价值，哪类任务仍需人工，哪些成功需要特殊配置。产品适用边界越清楚，越容易判断扩张是否会稀释结果。

该角度应产出：使用前后对照、关键价值机制、验收指标和适用边界。功能清单可以保留为资料附录，但不应替代价值分析。

### 7.3 起点与资源

创始人履历、关系、技术、供应链和品牌，只有进入经营动作后才构成实际优势。逐项追问资源解决了什么困难，是否已经投入业务，以及其他团队能否获得类似资源。

| 资源 | 可能降低的困难 | 应核对的证据 |
| --- | --- | --- |
| 行业经验 | 需求理解、采购沟通 | 具体判断、早期客户反馈 |
| 客户关系 | 首批触达与试点 | 介绍来源、成交记录 |
| 自有受众 | 分发与信任建立 | 可触达人数、实际转化 |
| 技术与知识 | 效果、成本或交付能力 | 对照测试、专有流程 |
| 供应链与伙伴 | 供给、产能和履约 | 合作条件、实际容量 |
| 资金与组织 | 持续试验和服务能力 | 可用资源、投入期限 |

区分接触资源与控制资源。认识某位专家，不等于拥有其固定投入；一次合作，不等于可持续渠道；融资可以延长试验时间，但不能替代客户价值。

还应区分起步优势与持续优势。创始人的人脉可能解释第一批客户，却不能证明陌生客户也会购买。早期手工交付可能有效，却需要额外能力才能规模化。

该角度应产出资源承诺表，记录控制者、实际投入、持续时间、替代难度和证据。不要只排列团队 Logo 或过往职位。

另列团队与分工表，每人一行：角色、相关背景、实际负责事项、投入承诺和来源。负责人清单区分已确认责任、拟议安排、未知；研究外部公司时只写可核实部分，不用创始人背景代替实际分工，也不擅自替其指派任务。

### 7.4 获客与成交

重建一位客户从发现公司到付款的过程，区分曝光、有效线索、试用、激活、报价和成交。每个环节都要明确事件定义、客户分母和观察窗口。

来源归因应区分公司渠道、创始人渠道、客户推荐和合作方渠道。一次联合活动成功，可能主要由合作方贡献；如果归因不清，就无法判断公司自身的获客能力。

进一步研究成交工作量。是否需要多次演示、定制方案、内部审批和安全审查？销售周期是否与客户规模有关？哪些客户在实施前付款，哪些要先免费试点？这些差异会影响成本和现金流。

漏斗之间必须使用可比人群。某个月新增线索不能直接与另一个历史批次成交数相除；同一客户重复提交也不应被计为多个独立机会。样本很小时，报告绝对数量及其背景，避免把单次比例当成稳定参数。

该角度应产出带来源和耗时的转化链路，以及主要流失原因。若只拿到公开数据，应把渠道机制与实际转化效率分别标注。

### 7.5 收入与成本

先说明谁为哪项价值、按什么单位、以什么频率付钱。订阅、按次、按席位、项目制、广告和交易抽成，对增长与成本的要求不同，不能只用总收入比较。

区分订单金额、收款、会计收入、经常性收入和利润。平台交易额通常不能直接视作平台留存收入；融资和资助也不能等同客户付款。年度预收款改善现金时间分布，但对应的服务责任仍然存在。

做一个与决策匹配的单位经济模型：收入减去可归属的交付、支持、交易和使用成本，再单列获客、实施及固定费用。科目是否计入毛利或贡献，应写清口径，不把教学模型冒充正式会计利润。

| 指标 | 本报告采用的分析口径 | 使用限制 |
| --- | --- | --- |
| 单位月贡献 | 月收入减去明确列出的可变服务成本 | 尚未扣除的费用必须列明 |
| 获客成本 CAC | 对应客户批次的销售营销投入除以新增付费客户 | 需要匹配时间和渠道 |
| 简化回收期 | 待回收前期投入除以稳定月贡献 | 依赖客户持续付费及贡献稳定 |
| 收入留存 | 同一批客户期末收入除以期初收入 | 说明扩张、降级和流失口径 |
| 生命周期价值 LTV | 生命周期内贡献的估计 | 短历史、小样本不宜机械外推 |

再问客户增加一倍时，哪些成本会同步增加。人工服务、物流、推理、审核和售后都可能构成容量约束。增长有时改善单位成本，也可能引入更复杂的客户和更高服务负担。

该角度应产出收入结构、成本结构、关键敏感变量与现金压力。即使无法拿到真实财务，也可以做明确标注的情景分析；不要把估计写成已知经营事实。

### 7.6 留存与增长

先研究同一客户为何继续使用或再次购买。持续价值、产品嵌入工作流、迁移成本和合同锁定都可能影响留存，它们的商业意义不同。订阅尚未到期，也不能自动视作客户愿意续约。

按相近进入时间、客户类型和渠道观察批次表现。激活、使用深度、续费、扩张、流失与回流，应与产品的自然使用周期对应。低频产品不一定需要高日活；高频产品的一次购买也不足以证明长期使用。

再检查上一轮业务留下了什么。客户成果可能带来推荐，交付经验可能成为模板，新增供给可能改善匹配。每一条反馈关系都应说明中间机制、衡量方式和失败条件。

增长循环可以写成“输入—业务动作—产出—重新进入输入”。若产出并没有提高下一轮效率或价值，它更接近线性流程。更多数据只有被有效使用并产生可测改善时，才可能强化业务。

该角度应产出留存原因、客户批次表现、增长反馈图，以及已验证和待验证的箭头。不要把五个带箭头的方框直接视为网络效应。

### 7.7 竞争与壁垒

竞争分析从客户的备选方案出发，包括直接产品、内部开发、人工处理、外包和继续忍受问题。真正的替代关系取决于客户任务，不取决于公司是否自称属于同一行业。

按效果、总成本、采用门槛、风险、信任和迁移难度比较。竞争对照表应使用同一客户场景，否则不同业务的优点可能被错误相加，产生一个现实中不存在的“最好产品”。

把优势写成可检验机制。例如，“客户更换系统需要重新配置大量业务流程”比“粘性强”具体；“相同任务的交付成本持续较低”比“技术领先”更容易调查。还要解释竞争者为什么不能快速复制，以及客户是否真正重视这种差异。

外部依赖也可能削弱优势。平台规则、关键供应商、少数大客户或通用技术的变化，都可能改变公司与其他参与者的议价关系。必要时画出价值链，判断公司创造的价值有多少最终由自己保留。

该角度应产出替代方案矩阵、优势的形成机制、维持成本与失效条件。融资规模和功能数量可以提供背景，但不能独立证明护城河。

### 7.8 阶段与约束

将前七个角度汇总，区分已经证明、有初步信号、未知和出现反证的事项。一个公司可能在需求上较强，在获客或经济性上仍然薄弱，不宜只给一个模糊的总分。

识别关键约束时，构造反事实：“假设明天这个问题被解决，目标指标是否会明显改善？”如果订单翻倍只会放大交付亏损，缺流量就可能不是当前最重要的约束。

约束可以来自需求、信任、渠道、交付、单位经济、资金或组织。确定主判断后，保留合理的替代解释，并指出需要什么资料才能区分它们。

该角度应产出一项主要经营判断、少量关键依赖，以及能够改变判断的证据。建议强度应与证据强度相匹配。

## 八、关键资料拿不到，怎样问才会推进判断

先按可获得性把未知分成四类。公开可查的由 Agent 继续查；已授权内部记录可得的先自己计算；只有用户知道的目标、未记录的承诺或意图才少量提问；都不可得的保留条件性结论及取得方式，其中只能由未来行为回答的转成验证计划。价格、付款等如果已有可核对记录，也应先查。不要把检索工作转交用户，也不要要求用户猜测目标公司的内部指标。

每轮通常提出 1–3 个会改变判断的问题。每题包含已知背景、缺口、为什么影响选择，以及便于回答的口径。允许“不知道”“不方便”或区间回答；没有回答不是默认同意。等待期间继续不依赖该答案的工作。

| 当前缺口 | 可以怎样问 | 回答改变什么 |
| --- | --- | --- |
| 用途未明确 | 这次主要希望理解公司的机制，还是决定自己的下一步？ | 输出研究解释还是经营路线 |
| 资源只有意向 | 当前有哪些人或渠道已承诺投入？能给投入时间、容量和条件吗？ | 哪些起点资产真的可用 |
| 报名与付款混用 | 最近一批总人数、实际付款人数、金额与退款分别是多少？可给区间。 | 需求证明及先收费还是先扩获客 |
| 使用与成果混用 | 这批人在哪个窗口内完成了什么可验收结果，达标人数和分母是多少？ | 交付效果及下一验证 |
| 收款与容量不明 | 每次交付包含哪些人的多少工时，返工和支持是否算入？ | 是否能重复交付及扩张边界 |

问题只在对话尚未提供答案且确实影响任务时提出，不把整张表一次发给用户。外部研究只询问用户可能持有或能授权提供的资料，拿不到也可以完成有边界的机制分析。

回答进入判断链，而不只是追加到附录。先记录日期、口径、来源身份和估计范围，再按“原判断 → 新证据 → 上调／下调／维持及理由 → 路线和行动变化”更新。受影响的证明状态、资产匹配、对标、迁移分类、首屏、图表和计划都应同步修改。

例如，用户确认已付款但尚未达到约定成果，可以上调收费证明，保留效果缺口，并把下一验证指向结果与交付；不能同时宣布需求、结果和复制都成立。正式提问与更新检查见 [问答合同](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/research-contract.md#怎样提问才有用)。

## 九、怎样把分析做成读者能用的页面

### 9.1 先安排阅读任务，再决定目录

读者通常先判断“这家公司是什么、主要结论是否值得继续看”，随后理解业务与机制，最后核实来源或作出下一步选择。因此，分析框架的分类不能直接等同于页面目录。目录要用具体产物命名，让读者知道点进去会得到什么。

主页面按“研究对象本身 → 决策与下一步 → 公司对标 → 证据”组织。下表是一份可调整的页面议程，节数随研究问题改变；不要为了固定数量生成空节，也不要把每条记录变成目录项。

| 阅读部分 | 主页面应完整呈现什么 | 适合继续深挖什么 |
| --- | --- | --- |
| 执行结论与现状 | 对象、时期、截止日、主判断、关键指标、全部证明命题和主要未知 | 数字定义、同批口径、对账、判断变化 |
| 产品、渠道、资产、团队 | 产品与交付、入口与控制权、资源投入、逐人职责与证据边界 | 互补资源怎样促成首批交付 |
| 自身路径与回路 | 全部关键动作及结果、每条反馈边和证据状态 | 人工过程、失败尝试、并行阶段与约束 |
| 历史决策与机制解释 | 关键选择、当时信息、观察结果、竞争解释和反证 | 当时的选择空间、机会成本及取证推导 |
| 当前选择与下一步 | 借鉴顺序；有决策任务时加全部建议、主路线、门槛、确认项与行动；所需数据合同 | 选择如何随证据改变、继续与停止条件 |
| 横向对照与逐家入口 | 完整矩阵、时期、差异、资产缺口与迁移条件 | 每家公司同结构拆解，重点案例四模块 |
| 证据与关键问答 | 来源身份、位置、支持范围、局限；未决问题及判断影响 | 返回每条使用该证据的记录 |

外部研究的“下一步”是调查与借鉴条件；用户业务决策的“下一步”才包括自己的运营责任与试验安排。两种任务不能仅换页面标题而保留同一套行动内容。

### 9.2 主页面完整，子页增加论证深度

每个主节使用“论点 → 完整结构化产物 → 结论与限制 → 可选深挖入口”。论点是对本次研究对象可被证据支持或推翻的判断，不是“本节列了什么”的说明；结论写它对选择或调查的意义，限制具体到单条记录。证据不能区分解释时明确分歧与区分证据，不强行给最可能的答案。

不点击子页，读者也应看到全部证明命题、关键步骤、决策、反馈边、建议、路线、行动、数据约定和矩阵行。条目文字可以精炼，不能只留一个摘要或把影响判断的内容默认折叠。

子页扩展口径、证据、推导、反例和逐家公司拆解；它不能成为主页面缺项的补救。专题是否单独成页由论证深度决定，不由表格行数决定。常见专题包括横向对照、建议复盘、关键决策、数据核验和重点公司路径；按任务选用，不能凑空页面。

每个子页首屏给父节返回、一句话判断、证据边界和论证路线；正文用 3–6 个递进模块，不另设侧栏；末尾回到行动或调查。涉及借鉴路径的重点对标独立成节，在主页面列全关键步骤，子页沿“互补资产 → 首次交易与交付 → 取舍与反模式 → 回路与迁移”展开；外部研究的目标自身路径也按四模块拆解。主页面和子页引用同一份记录，避免维护两套数字。

### 9.3 图表形式必须对应判断任务

| 要表达的关系 | 优先形式 | 必须保留的语义 |
| --- | --- | --- |
| 已经证明到哪里 | 命题／状态／证据／缺口／下一步表 | 未知与反证不同，不适用有理由 |
| 各对象有何差异 | 同字段矩阵 | 时期、对象、口径、缺失及来源；不造无定义评分 |
| 动作怎样发生 | 时间线或阶段卡 | 日期、动作、结果、解释与并行关系 |
| 为什么作出选择 | 决策条目或前后对照 | 当时信息、备选身份、实际选择、后续观察、代价 |
| 用户如何转化 | 同批漏斗或分支图 | 相同对象、事件、窗口与分母；重叠分支不相加 |
| 指标怎样变化 | 序列表、比例条或批次表 | 单位、口径变化、未成熟批次；缺失不变成零 |
| 上一轮怎样帮助下一轮 | 回路图及逐边说明 | 回流动作、测量方式、证据状态与断点 |
| 钱和容量如何约束增长 | 收入成本拆解或情景表 | 科目、假设、范围、区间；估计不冒充实绩 |
| 下一步怎么做 | 采纳看板、路线卡、里程碑表 | 采用条件、责任、观察、继续与停止标准 |

图形负责关系，表格便于核对，正文解释原因。趋势不能仅因数值下降就画成流失漏斗；未经验证的反馈不能通过闭合圆圈制造已成立的印象。数字来源与限制应紧邻结果，不能全部移到页尾。

### 9.4 版式建立稳定的阅读层级

```text
首屏：对象与时期 → 主判断及边界 → 少量关键指标
主目录：扁平编号与具体产物名称，与正文顺序一致
主节：论点 → 完整表、图或路径 → 结论与限制 → 深入入口
专题：返回父节 → 论证路线 → 递进模块 → 回到下一步
证据：来源身份与位置 → 支持范围与局限 → 返回引用记录
```

主判断、章节论点、正文、口径与来源逐层降低视觉权重，但关键未知仍保持可读。未知的重要性取决于它对结论的影响：会改变主判断的缺口应出现在首屏或对应结果旁，不能藏进折叠区。

桌面用扁平目录保留位置，1280×900 下应能扫完主要议程；先缩短标签、合并相同阅读任务，不靠缩小字体硬塞。窄屏按原阅读顺序堆叠，目录可折叠，宽表在局部滚动，整页不能横向溢出。同类条目字段顺序一致，数值单位一致，颜色同时配文字标签。

具体尺寸、间距、导航与颜色规则由 [呈现规范](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/result-presentation.md) 维护。学习方法的说明文字与实际研究结果页承担不同任务，复用时应保留各自的信息层级。

### 9.5 交互应帮助比较、追证和更新

公司、关键词和事实／解释／建议筛选服务于核查。页面明确显示当前组合条件、结果数、空状态与重置入口；事实视图仍保留理解事实所需的分母和限制。首屏若不随筛选变化，应明确其范围，不能让读者误以为它是筛选结果的经营汇总。

结论、数字、问题、行动和来源使用稳定标识，支持从判断到来源再返回原记录。深链应进入包含目标的主页面或专题，恢复必要筛选并聚焦。来源不只是页尾链接清单，还要写支持范围与局限。证据库前展示整份研究的覆盖清单：检查对象、状态、对应记录、缺口或不适用原因。它不随正文筛选变化；数据校验检查缺项、重复与失效引用，人工仍需核对是否有实质依据。

静态报告只能展示已记录的问答；Agent 收到用户回答后核对并更新数据，再生成页面。不能让用户误以为页面会保存输入或自动推理。[交互模板演示](demo/index.html) 与 [外部研究测试示例](demo/external.html) 均使用明确标注的虚构数据，仅用于查看这些展示行为，不提供可直接引用的公司事实。

## 十、下一家公司的研究怎样执行到交付

第一轮建立任务范围、证明状态与资产快照。先读实际产品和原始资料，形成暂定判断，把关键未知按公开取证、授权内部复算、用户问答和不可得／未来验证处理。即使尚未补齐数据，也应能说明目前证明到哪里。

第二轮重建路径与选择，再按资产和问题选对标。逐家公司核对动作、结果和反馈，比较相似起点的不同路径以及相似动作的不同结果。将主解释、竞争解释和反证对应到证据，而不是继续堆公司简介。

第三轮用新证据与用户回答修正判断。有业务决策任务时确定当前路线、门槛、责任与阶段验证；外部研究则确定借鉴条件和取证优先级。数据合同约定下一轮需要的口径，不要求用户一次填写全部字段。

第四轮按页面议程组织完整产物和深入专题。复用统一记录生成首屏、表格、图与来源；逐项填写覆盖数据并展示未完成项，再验收展示。结构校验通过只说明字段和引用符合要求，不能替代研究事实与推理的核验。

停止收集资料的条件是：主判断能追到动作、口径、直接证据和反证；剩余关键缺口已有已查范围、判断影响与取得方式。没有必要为填满所有表格无限搜索，也不能用行业常识补造内部事实。

| 交付检查 | 通过标准 |
| --- | --- |
| 研究主线 | 能从证明状态走到实际资产、行为机制、迁移条件与下一步 |
| 证据与深度 | 每家重点对象有实质拆解；数字可追证，反证和未知明确 |
| 问答闭环 | 用户回答改变相应判断、图表和行动，而非只存入附录 |
| 主页面完整 | 不进入子页即可阅读每项主产物；章节顺序支持判断 |
| 专题深度 | 增加口径、推导与证据分析，有父节与下一步返回 |
| 展示可用 | 桌面和窄屏下目录、正文、宽表、来源、筛选与深链可用 |
| 交付范围 | 文件可访问、格式符合要求；未完成的运行或离线检查如实说明 |

完整内容核对使用 [研究合同覆盖清单](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/research-contract.md#内容覆盖清单交付时逐项填写)，展示核对使用 [呈现验收](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/result-presentation.md#展示验收)。数据格式、单文件导出和复现命令使用 [模板约定](https://github.com/caiboyang/ML-learning/blob/main/.agents/skills/company-research/references/dashboard-data.md)。后续换公司时复用的是研究顺序、判断标准和展示关系，全部公司事实与适用条件重新核对。
